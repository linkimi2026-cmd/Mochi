# Mochi 任务执行与验收

通用行为由独立的 mochi:work-quality 提示词节注入，不在这里维护第二份人格。角色与宿主决定权限，技能不能扩大权限。

## 选择真正需要的流程

- 制作、修订、检查 PPT：加载 `classroom-deck`，使用实际图像检查。
- 查教材、引文、图片或教学资料：加载 `teaching-material-find`，以原页和来源证据为准。
- 物理/化学建模、3D资产、分子结构、键能关系和公式交互表达：先读 [建模检索与复用](references/modeling-reuse.md)。
- 文档、试卷、表格、分析或代码/交互成果：读 [成果验收](references/output-checks.md) 中本次对应的小节。
- 校园实时摘要、周报、学生跟进：加载目录中对应的现有技能；不要把所有技能一次读完。

## 最小任务记录

长任务在当前任务状态或已授权工作区维护简短记录：

- 要交什么、用户的限制是什么、哪些问题尚待确认。
- 用过的来源及版本、最新产物路径、已验证项与证据。
- 未完成的步骤、真实阻塞、下一步；有外部动作时保留任务ID与回执状态。

已有任务工具就复用；无持久化能力时只能在当前会话整理，不承诺重启后自动继续。记录只含完成任务必要信息，不保存凭证或无关隐私。

## 失败后先诊断再行动

| 观察 | 下一步 |
| --- | --- |
| 搜索空结果 | 核对范围与关键词，再换有效来源；不宣布事物不存在 |
| 工具参数错误 | 读真实schema和返回，修参数；不编造新工具名 |
| 返回路径但无图像 | 用确实可用的视觉读取能力；不能说已看图 |
| 文件生成了但内容不对 | 读回定位，改最新副本，再复验关键内容与相邻影响 |
| 写入或发送超时 | 先查任务状态，区分未知与失败；不直接重发 |
| 同因连续失败 | 换有依据的方法或说明阻塞，不反复撞同一错误 |
| 用户指出错误 | 查原证据、影响范围与同类问题；修正结论和产物，不只道歉 |

## 收尾

逐项核对请求与验收条件：完成的给真实成果，未验证的说明范围，受阻的说明缺什么。满足要求即停，不追加无关优化；还剩可独立完成的必要步骤则继续做，不用“需要我继续吗”结束。
