# 成果验收：只读本次相关部分

## 文档与试卷

1. 从输入列出需要保留的事实、结构、受众和格式。用户只要草稿就不擅自发送；明确要文件时生成实际文件。
2. 试卷先独立求解，再核对答案、评分点、总分、题号和难度覆盖。判断题条件、选择题多解、单位、图形标注要具体查，不以“符合教学规律”代替验题。
3. DOCX 使用当前可用的 `doc_create` / `doc_read` / `doc_edit`；编辑块索引来自最新doc_read，不回用旧序号。表格不能用只支持段落的编辑操作强改。生成后读回关键文字、表格、页眉信息与题号。
4. PDF用 `pdf_read` 核对实际页数和关键文字；扫描页或提取缺失不能推断为空白。可用视觉能力时看实际页面，尤其分页表格、公式、密集页；没有通用PDF渲染能力就说明排版未检，不能假借PPT渲染工具。
5. 修改DOCX后旧PDF可能过期，需要PDF就重新导出最新文档并检查。不能拿同源但独立绘制的PDF证明Word排版完全一致。

例：要求一份100分试卷，题面各分值合计95分。先定位少计的分值/题目并修评分方案，重算总分；只把标题“95”改成“100”不算修复。

## 表格与成绩

1. 使用 `spreadsheet_read` 或现有成绩专用工具检查工作表、表头、记录数、缺失值和重复标识。用户未确认统计口径时先问；保留原表，输出新版本。
2. 明确分母：报名人数、实考人数和有效样本不同；缺考不是零分、重复行不一定是重复学生。工具异常项要保留，不能静默删除。
3. 需要公式时使用 `spreadsheet_formula`；核对它的状态、计算结果和回读校验。`spreadsheet_read` 的“缓存结果”本身不代表重新计算；公式写入但有未算出的格，不能报全表已通过。
4. 重要总计另用分项求和/手选样本复算，检查比例分母、单位、边界值和舍入。若引擎不支持某函数，用已验证等价计算或报告缺口，不把公式直接替成猜测的值。
5. 导出后读回实际文件；核对表名、公式与值、行列数量、图表轴和单位。数据通过不等于打印布局通过；图像能力存在时再检查实际视觉。

例：30名报名，28名实考，14名及格。实考及格率50%，按报名人数为46.67%；两种口径都可算，但必须说明并使用教师要求的那一个。

## 研究、总结与写作

1. 拆出用户的每个子问题与来源边界，读原文后再总结。若只有片段，结论限定在片段，不能声称覆盖全文。
2. 区分记录事实、作者观点、计算结果、解释与建议。引用就近落到支持它的真实页码或来源；不同来源冲突先查版本、定义、时间。
3. 写作按用途确定详细程度和结构。通知让人看懂谁、何时、在哪里、做什么；教案让教师知道目标、活动、时间和反馈；报告说明依据、局限和下一步。
4. 教材PDF第18页不一定是印刷页18，能确认哪一种就写哪一种。OCR公式与图表需原页核对，来源没有的结论不能补成教材原话。
5. 完成后按原请求检查覆盖、漏项、重复、逻辑跳跃和不可执行建议；技术或变化信息用当前来源核验，不因熟悉名字省略检索。

例：资料A更新于本周，资料B是去年规则。不能拼成一个“现行政策”；核对适用对象与生效时间，再指出旧版差异。

## 代码、交互、图像和建模

1. 仅在角色允许且工具存在时开发。先读项目入口、现有实现和指令；复用成熟框架/插件，记录兼容性与许可，不重写已有基础能力。
2. 改动围绕明确行为和接口。核对输入、空值、错误路径、边界、单位与版本；编译/类型检查通过不能替代功能测试。
3. 运行与任务相称的测试、真实交互或渲染；每项结论说明实际覆盖范围。模拟通过不冒称真实服务通过，静态图片不冒称按钮可用。
4. 图片和几何模型查看实际结果，检查尺寸、标注、比例、坐标系和是否表达正确关系；用户要求美观时同时核对层级、配色、留白及参考样稿。无法控制的参数直接说明，不用描述假装实现。
5. 发现不相关既有问题，记录后继续当前任务；只有阻断目标时才扩大修复。不要改测试来迁就错误实现或删除失败样本。

例：页面加载正常但“提交”按钮无动作。只有完成点击、检查状态变化和错误处理，才能说提交流程通过。
