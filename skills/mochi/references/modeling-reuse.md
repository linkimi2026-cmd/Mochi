# 建模：先检索，再决定复用或生成

适用于物理仿真、化学结构/反应示意、3D模型、分子键和能量关系、数学公式与交互表达。

1. 明确目标：展示还是定量计算；学段、对象、单位、格式、离线要求、交互范围。分子结构、键线式、键能曲线不是同一对象；含糊且影响正确性时先确认。
2. 用当前真实web_search/web_fetch等工具，先以对象中文原名和英文关键词检索GitHub完整应用、仿真项目与模型资产，再查可复用组件。最多先看2–3个相关候选；方向明确后停止漫搜。不能只搜自己已决定采用的库。
3. 对候选读取实际代码/文件、README、许可证及依赖：记仓库URL、版本或提交、格式/文件大小、维护情况；3D资产检查是否LFS指针、坐标轴、比例与纹理，不能把网页预览当可下载模型。科学模型核对方程、假设、单位、边界与适用范围；GitHub公开不代表有可复用许可证。
4. 满足任务且许可/依赖适配就复用，并保留归属；部分适用则复用基础能力、补必要差异。找不到合适结果就用已有受管工具或获授权的脚本自行生成。无权限、网络失败、没有命中、找到了但不适用分别说明；用户明确离线或禁止外网时尊重限制，说明未检索后继续可做部分。
5. 在当前任务记录保留简短复用结论：搜索词、候选来源与版本、采用/不采用理由。不要为每个建模任务创建工程级审计文件；已有项目要求docs/reuse-audit.md时按项目规则执行。不安装整个仿真生态来完成一个小示意，也不把第三方脚本未经核对就运行。
6. 生成后分别验证科学正确性、交互和视觉：解析解/守恒或边界例、参数与单位、实际拖动/缩放/旋转、真实截图与文本可读性。3D外观不能证明物理准确；分子渲染不能证明能量正确；示意曲线必须标注假设，不能捏造实验数据或键能数值。

当前mochi_model_create仅支持conic-tangent椭圆切线，不支持任意物理/化学/3D类型。不得传入虚构type；其他任务只能使用当前目录真实存在且获授权的通用能力，能力不足则明确交付范围。

检索方向而非预先批准依赖：PhET完整教学仿真（逐仓库核许可与构建复杂度）；3Dmol.js分子可视化、RDKit化学结构处理；3D资产检索对象名+glTF/GLB；公式展示与科学求解分开选择。任何候选均须本轮核验，不承诺安装兼容。
