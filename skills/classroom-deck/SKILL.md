# 课件制作（含设计规范）

## 先读规范

生成任何课件之前，**按顺序读这三份文件**（用 `read` 工具读绝对路径）：

| 顺序 | 文件 | 管什么 |
| :-- | :-- | :-- |
| 1 | `plugins/mochi-presentations/references/design-principle.md` | 通用设计法则：密度、色彩、字体阶梯、视觉锚点、硬闸门 |
| 2 | `plugins/mochi-presentations/references/designs/design-principle.classroom.md` | 课堂与答辩场景的具体色值与版式规则 |
| 3 | `plugins/mochi-presentations/references/story-principle.md` | 内容叙事：角色、节奏、标题写观点、数据要落点 |

> 这三份是 Mochi 自己的设计宪法。**不要凭"感觉好看"生成**——AI 凭感觉生成的课件，
> 典型缺陷是「页页四个卡片、每页只有两三行字、标题全是分类名」，这正是最丑的形态。

## 工作法

1. **先对齐意图**（只问缺失的，一轮问完，≤3 个问题）：受众、场合、时长、调性、必讲与不讲。
   已有信息足够就直接开始，不要为了走流程而追问。

2. **再定骨架**：章节划分、页数、哪几页是重页（20–30%）、节奏曲线。
   骨架未定不要开始写逐页内容。

3. **逐页大纲**：每页写出 `role` / `rhythm` / `layout` / `density` / `anti_pattern` / `takeaway`。
   - 标题要写**观点**不要写分类名（`温度每升高 10℃ 速率约翻一倍` ✅ / `实验数据` ❌）
   - 关键数据必须补一句判断，只摆数字的页面是信息板不是课件

4. **生成课件**：整理为每页 `{heading, bullets}`，调用 `mochi_ppt_create`。
   需要比较数据时额外给 `table` 或 `chart`（二选一）。
   内容密度按规范 §4 执行：正文页 ≥180 字、内容区占用 ≥90%。

5. **渲染回看（强制步骤，不可跳过）**：调用 `mochi_ppt_render` 渲染成图，
   自己看一眼再交付。检查项：
   - 哪几页明显偏空？内容撑不满？
   - 文字有没有被裁切、溢出、压在一起？
   - 配色是否失衡？锚点是否够醒目？
   - 全篇节奏是否有起伏，还是页页一个重量？

   **这一步无法用别的方式替代**——排版溢出、元素重叠、文字被裁切这类问题
   在 OOXML 结构里完全看不出来。你对着一份"结构完全正确"的 XML，
   是发现不了"Agent 被裁成了 gent"的。视觉问题只有眼睛能发现。

6. **修改与复验**：发现问题就用 `mochi_ppt_revise` 定页修改，改完**再渲染一次**确认。
   至少完成一轮「渲染 → 发现问题 → 修改 → 再渲染复验」，才允许交付。

7. **交付**：返回 PPTX 路径、页数、`sourcePath`，并说明本轮做了什么视觉修正、还剩什么需要老师拍板。

## 常见失败形态（对照自查）

| 失败形态 | 症状 | 规范出处 |
| :-- | :-- | :-- |
| **空** | 一页只有几个字配大空白 | 通用 §4 密度门禁 |
| **均匀稀薄** | 每两个元素之间空隙都一样大 | 通用 §4.3 留白策略 |
| **无锚点** | 所有元素大小趋近中间值 | 通用总则 §2 |
| **阶梯过平** | 标题 32px、正文 28px、注释 24px | 通用总则 §3 |
| **流水线感** | 页页都是卡片组，视觉重量相同 | 通用 §5 节奏约束 |
| **信息板** | 数据只摆数字不给判断 | 叙事 §数据必须落点 |
| **提纲化** | 标题全是分类名（"实验数据""课文分析"） | 叙事 §标题要写观点 |
| **裁切** | 文字溢出色块被切掉 | 课堂 §7 闸门 11 |

## 教师场景红线

- 公式、定理、数据、史料、引用**必须真实可考**，禁止杜撰。
- 课堂示例数据必须标注"示例"或来源。
- 涉及具体学生成绩只能做班级整体分析，**不得指名道姓做负面评价**。
- 练习页必须留 ≥35% 答题空间。
- 成品只能是 `.pptx`（要讲义才附 PDF）；**禁止用 HTML 或截图冒充课件**。
