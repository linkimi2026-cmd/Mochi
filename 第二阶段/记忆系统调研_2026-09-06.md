# 记忆系统调研报告

调研日期：2026-09-06
调研范围：LLM Agent 记忆系统的学术机制（含遗忘）与开源实现
核实方式：GitHub API + ungh 代理交叉核对 star/license；源码级 curl 抓取验证参数真实性
边界：本报告只覆盖记忆系统。**双界面部分由用户自行接手，不在本报告范围内。**

## 摘要

| 问题 | 结论 |
|---|---|
| 理论基础 | **MemoryBank 的指数衰减** + **Zep 的双时态** + **MIRIX Knowledge Vault 免疫区** 三者组合即可，不必上完整框架 |
| 现成底座 | **SimpleMem**（MIT，纯 stdlib sqlite3，唯一真做了衰减）为首选思路源；**mem0 OSS** 为工程化备选（但 OSS 版无衰减，需自补） |
| 最大风险 | 记忆做得糙会**拖垮**模型（A-MEM 消融：9.65 < 不做记忆基线 25.02），必须配引用率护栏 |
| 落地成本 | 两步：①`world-state.md` 纯文件 1–2 天 ②SQLite 衰减+冲突消解 3–5 天 |

### 1.3 遗忘机制（核心）

| 方法 | 年份 / 编号 | 机制 |
|---|---|---|
| **MemoryBank** | 2023 AAAI24 · arXiv:2305.10250 | **R = e^(−t/S)**；S 首次提及初始化为 1；每次被召回 S += 1 且 t 归零。三原则：遗忘速率、时间衰减（先陡后缓）、间隔效应 |
| **Generative Agents recency** | arXiv:2304.03442 | recency = **0.995^（沙盒小时数）**；检索打分 = α_rec·recency + α_imp·importance + α_rel·relevance，三项先 min-max 归一化到 [0,1]；**原文 α 全设为 1**（网传 1/1/2 是工程变体） |

### 1.4 检索机制

| 方法 | 年份 / 编号 | 机制 |
|---|---|---|
| **HippoRAG** | 2024 NeurIPS · arXiv:2405.14831 | 离线 LLM 抽三元组建无 schema KG + 同义词边；在线 query 抽实体 → 链接节点为种子 → 跑 **PPR**；node specificity = 1/(含该短语的段落数) 乘在查询节点概率上 |
| **HippoRAG 2** | 2025 ICML · arXiv:2502.14802 | 段落节点入图（dense-sparse integration）；**recognition memory：在线用 LLM 过滤掉不相关三元组再播种 PPR** —— 这是防上下文污染的机制，值得抄 |

### 1.5 冲突消解

| 方法 | 编号 | 机制 |
|---|---|---|
| **Zep 双时间模型** | arXiv:2501.13956 | T'（系统时间线：created_at/expired_at）与 T（现实时间线：valid_at/invalid_at）。新边与旧边矛盾 → LLM 判定后把旧边 `invalid_at` 设为新边 `valid_at`，**不删除，保留历史**。"张三销假" = 新增一条 valid_at=今天的边，旧边置 invalid_at |
| **Mem0 Update 阶段** | arXiv:2504.19413 | 取 top-K(K=10) 相似记忆与新候选事实一起喂 LLM，function-call 选 **ADD / UPDATE / DELETE / NOOP**。四选一 prompt 很短，glm-4-flash 够用 |

### 1.6 元记忆

- **Self-RAG**（2023 ICLR · arXiv:2310.11511）反思 token：Retrieve{yes,no,continue} / IsREL / IsSUP / IsUSE；检索触发阈值 P(Retrieve=yes) > 0.2。不训练也能用：让 glm 每轮先输出 `need_memory: yes/no`，no 就直接答，省 token
- **MIRIX Active Retrieval**：用户提问后**先生成 topic** 再跨组件检索，结果标注来源类型后注入 system prompt。比"拿原话去向量搜"召回好，且 topic 可缓存

### 1.7 未查证项（诚实标注）

- 「不该忘的硬约束」无专门论文。最接近的是 MIRIX Knowledge Vault 与 MemOS 治理属性，均为工程机制而非理论
- **context pollution / memory bloat 没有统一的学术度量指标**，下文 3.7 的引用率是工程代理指标，非论文结论
- 真正的「Agent 自知己不知」metamemory 方法未查证到

## 二、⚠️ 最重要的一条警告

> **A-MEM 消融实验（GPT-4o-mini，多跳 F1）：**
> 无链接无演化 **9.65** → 仅链接 21.35 → 完整 **27.02**
> 而**不做记忆的基线是 25.02**

**切碎的检索式记忆，做得不好比完全不记忆更差（9.65 < 25.02）。**

记忆系统不是"加上就变强"——做得糙会**拖垮**模型表现。这条决定了两件事：

1. 引用率护栏（3.7）必须在第一版就埋进去，不能等出问题再补
2. 宁可第一版记忆少而准，不要多而杂

## 三、遗忘机制落地清单（可直接编码）

**3.1 衰减公式**
`R = exp(-t_days / S)`；S 初始 1，每次被注入上下文并真正被引用时 `S += 1; last_recalled_at = now()`。`R < 0.05` 标记 `cold` 而非删除，便于召回审计（MemoryBank 原文公式）

**3.2 检索打分三因子**
`score = 0.35*norm(recency) + 0.30*norm(log(S)) + 0.35*cosine(q, e)`
Generative Agents 原文 recency = 0.995^小时；按「天」改底数 **0.97**；短对话场景把相关性权重提到最高

**3.3 免疫清单（永不衰减，跳过所有清理）**
① 教师显式说「记住/别忘了」② 安全与合规规则 ③ 学生过敏、特殊照顾、请假状态等状态型事实 ④ Knowledge Vault 条目（联系方式、班级花名册）
实现：`pinned INTEGER DEFAULT 0`

**3.4 分层清理，别一刀切**
- 语义事实：**只做冲突消解不做时间删除**（照 Zep：`invalid_at` 置位，行保留）
- 情景事件：时间衰减 + 30 天批量摘要压缩
- 免疫清单与程序性规则：**只做版本更新不删**

**3.5 压缩触发**
单班情景记忆 > 500 条，或距上次 consolidate > 7 天，或当日新增 > 40 条 —— 任一命中在空闲时段（5 分钟无操作）跑一次，输出 ≤5 条 insight，每条必须带 `source_task_ids`

**3.6 反思触发**
照搬原文「importance 之和 > 150」成本过高。改为每天最多 1 次 + 当日 importance 之和 > 60（约 8–10 条普通事件）

**3.7 防「忘出笨」护栏（关键）**
每次检索注入后统计 `引用率 = 被明确引用的记忆条数 / 注入条数`
连续 20 次对话引用率 < 20% → 判定上下文污染，收紧 top-k（8→5）并上调相关性权重
**这条防的就是第二节那个 9.65 < 25.02 的坑**

**3.8 膨胀硬上限**
全库 active ≤ 3000 条；超限按 R 升序**归档**（不是删）到 `memory_archive`，归档行仍可被显式时间范围查询命中
删除只发生在用户手动触发，或 `pinned=0 且 R<0.05 且 90 天未被召回`

### 4.2 SimpleMem 源码级核实（curl 亲验，非二手）

文件：`simplemem/evolver/consolidator.py`，类 `MemoryConsolidator.__init__`

```python
decay_after_days: int   = 30
decay_factor:     float = 0.05
min_importance:   float = 0.15
decay_mode:       str   = "linear"      # "linear" | "exponential"
```

衰减实现（第 275–289 行，逐字摘录）：

```python
periods = (age_days - self.decay_after_days) / float(self.decay_after_days)
if self.decay_mode == "exponential":
    new_importance = max(self.min_importance,
                         unit.importance * math.exp(-self.decay_factor * min(periods, 10.0)))
else:  # linear
    new_importance = max(self.min_importance,
                         unit.importance * (1.0 - self.decay_factor * min(periods, 5.0)))
```

同时确认存在：
- `store.supersede(old_id, new_id)` **取代链**——标失效而非硬删，可审计可回滚
- `reinforced` 计数——记忆被访问会强化 importance（等价 MemoryBank 的 S += 1）
- 去重 + 近重复合并 + stale working summary 清理

### 4.3 三强对比

**首选：SimpleMem（3,752★，MIT）**
唯一真做了衰减、且能纯 stdlib sqlite3 跑的。零外部依赖，可与 `mochi_tasks` 同库。supersede 取代链对教育场景（请假改期、销假）刚好。
*代价*：社区规模小（393 fork），最近 push 07-24（约 6 周前），Python 进程需自己包进 Electron；写入仍需 1 次 LLM 做语义结构化，但**检索是向量+BM25 混合、0 次 LLM**。

**备选：mem0 OSS（64,748★，Apache-2.0）**
工程化最成熟。`add()` 两阶段：1 次 LLM 抽事实 + 1 次 LLM 与已有记忆比对决策 ADD/UPDATE/DELETE + 1 次 embedding；检索 0 次 LLM。可用 faiss/chroma 本地文件后端，完全不出本机。
*代价*：**OSS 明确没有衰减**——issue #6128「implement memory decay for OSS」仍 open，#6905 是「文档宣称的 decay 与 SDK 不符」。对"遗忘最重要"这条，它是半成品。

**省 token 参考：langmem（1,646★，MIT）**
`RunningSummary` 只摘要"未摘要过的消息"，按 token 阈值增量触发，不会重复烧 token。*代价*：绑定 LangChain/LangGraph，长期层无遗忘。

### 4.4 明确出局

- **graphiti**：遗忘设计最好，但**嵌入式后端已死**——issue #1132「Kuzu is archived」、#1469「add_episode crashes with Kuzu C-extension access violation on Windows」。涉及 Windows 支持即出局
- **cognee**：重，且 SQLite 引擎有 #3852（未开 WAL/busy_timeout 导致 database locked）、#4518（UUID 类型不通用），Electron 多进程下会踩
- **letta / MemOS / MIRIX**：agent 操作系统级，要常驻服务；源码树找不到成型遗忘实现；MemOS 仓库已转向 harness 方向
- **A-mem / Memary / HippoRAG**：A-mem 停更于 2025-12 且依赖 torch；Memary 停更近两年；HippoRAG 是研究代码不是记忆系统
- **memU**：license 是 `other`（非标准协议），二次分发有法务风险
- **supermemory / Zep Cloud**：SaaS，硬约束不符

### 4.5 若「只用思路自己写」，抄这 5 处

## 五、给 Mochi 的落地设计

### 5.1 表结构草案（合并上述五处，可直接用）

```sql
CREATE TABLE mochi_memories (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  scope_id         TEXT NOT NULL,                  -- 作用域：班级 / 教师
  kind             TEXT NOT NULL CHECK (kind IN ('episodic','semantic','procedural','vault')),
  content          TEXT NOT NULL,
  importance       REAL NOT NULL DEFAULT 0.5,      -- 衰减作用于此
  pinned           INTEGER NOT NULL DEFAULT 0,     -- 免疫清单：永不衰减
  strength         REAL NOT NULL DEFAULT 1.0,      -- R = exp(-t/S)
  recall_count     INTEGER NOT NULL DEFAULT 0,     -- S，每次被引用 +1
  created_at       TEXT NOT NULL,
  updated_at       TEXT NOT NULL,
  last_recalled_at TEXT,
  valid_at         TEXT,                           -- 现实时间线（Zep 双时态）
  invalid_at       TEXT,                           -- 置位 = 被取代，行保留
  superseded_by    INTEGER,                        -- supersede 取代链
  source_task_ids  TEXT,                           -- JSON 数组，证据引用
  version          INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_mem_scope    ON mochi_memories(scope_id, kind);
CREATE INDEX idx_mem_active   ON mochi_memories(invalid_at);
CREATE INDEX idx_mem_strength ON mochi_memories(strength);

CREATE TABLE mochi_memory_events (                 -- append-only 审计日志
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  memory_id INTEGER,
  event     TEXT NOT NULL,   -- created/recalled/reinforced/decayed/superseded/archived
  at        TEXT NOT NULL,
  detail    TEXT
);

CREATE TABLE mochi_memory_injections (             -- 引用率护栏的数据源
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id   TEXT NOT NULL,
  injected_ids TEXT NOT NULL,                      -- JSON 数组
  cited_ids    TEXT NOT NULL,                      -- JSON 数组
  at           TEXT NOT NULL
);

CREATE VIRTUAL TABLE mochi_memories_fts
  USING fts5(content, content='mochi_memories', content_rowid='id');
```

### 5.2 两步落地路径

**第一步：`world-state.md`（1–2 天，纯文件，零依赖）**
- AI 每次醒来读这一个文件，**200 行封顶**
- 内容：当前待办 / 近 24h 变更 / 已知约定
- 验证标准：第二天早上 AI 能直接念出"昨天有 3 条外出申请待批"

**第二步：SQLite 衰减 + 冲突消解（3–5 天）**
- 抄 SimpleMem 四参数 + supersede 链 + graphiti 双时间字段，用 5.1 的表结构
- **先不做向量检索**——glm-4-flash 场景下 SQLite FTS5 全文检索足够，且零成本、零依赖
- 引用率护栏（3.7）**第一步就埋进去**，否则会踩第二节那个坑
- 需要向量时再上 sqlite-vec，不必一开始就引入

### 5.3 隐私红线（延续项目既有裁定）

- **记任务不记人**：记"3 条外出申请待批"，不记"李老师 9:14 打开了申请页"
- **记结果不记轨迹**：记状态变更，不记操作流水
- **可查看、可一键清空**：老师能打开 `world-state.md` 看 AI 到底记了啥
- **本地存储，不上云**
- 学生数据经 `skills/teaching-material-find/` 已有隐私门禁复查

### 5.4 Archify 的定位（衔接前一轮裁定）

Archify **不进记忆链路**。它画的是拓扑（谁连谁），记忆要的是事件流（发生了什么）。
它的落点是开发者侧：画 Mochi 自己的架构图做答辩材料。
