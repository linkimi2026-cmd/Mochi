## 0. 这份文件解决什么

这条片子的难点不是特效，是**判断**：哪一拍该留白、哪两个物件之间能长出下一幕、哪句话是假的。

所以先落三样东西：**事实源**（我们只能讲什么）、**视觉系统**（画面长什么样）、**分镜与转场图**（每一秒发生什么、为什么下一幕能接上）。三样定稿后再写一行动画代码。

### 1.2 三条被推翻的旧设定（**必须换掉**）

1. **品牌蓝 `#3F5B99` 已死。** V4–V7 全片围绕这个蓝 + 墨绿 `#283d35` + 纸白 `#faf8f2`，在当前 `client-plugins/` 里 **grep 零命中**。现在的品牌色是**鼠尾草绿 `#45584e` + 暖橙强调 `#d9873e` + 暖米白画布 `#f6f3ec`**。沿用旧蓝 = 一开口就过期。
2. **本尊不是"蓝边手绘球 + 小电脑 + 双手"。** 现在是**焦糖实心球（`#a06a32`）+ 两道奶油细缝眼 + 面前小电脑**，且**没有双手**。V7 那套是过期的。
3. **本尊的"活"是有引擎的。** `bloub-motion.ts` 里躺着 `idle / thinking / typing / celebrate / alert / sleep / boot / sending / listening / speaking` 十种状态与 `orbit / swirl / comet / play / burst / wink / wide / notify / exclaim / egg / hexagon` 十四种姿态。影片里 Mochi 的每一个动作**都由同一台引擎驱动**，不手摇。

### 1.3 影片只允许讲的东西（硬约束）

- **可以讲**：对话 / 工作模式；四类真实产物（`.pptx` / `.docx` / `.xlsx` / 交互式模型页）；知识检索；成绩分析（真 `.xlsx` 审计工作簿）；建模（**本期只有椭圆切线 `conic-tangent`**）；办公三件套的读写与修订；A2A 派发与五状态（已发送/已送达/已完成/已拒绝/结果未知）；小信箱；工作日记（`world-state.md`）；节日问候；rail 两种形态；教师↔教室局域网投递与「已看到」回执；人工确认卡；对话/工作模式。
- **不许讲**：教材库命中（**本机教材库当前为空**）；抛物线以外的数学建模；PPT 里的图片/自由坐标/字体/动画；"AI 不会出错"；"替代老师"；任何用户量、效率提升、准确率等没有证据的数字；把校内记录说成实时定位。
- **必须标注**：凡出现学生数据 → 角标「演示数据 · 虚构」。
- **不出现**：模型名称（身份口径 + 评审观感）。

## 2. 视觉系统定稿

### 2.1 色板

| 角色 | 值 | 用在哪 |
|---|---|---|
| 画布 | `#f6f3ec` | 纸白世界的地面 |
| 表面 | `#fffdf8` | 卡片、窗口、抽屉 |
| 墨 | `#34332f` | 正文 |
| 次级 / 弱 | `#666258` / `#767166` | 说明、标签 |
| 品牌 | `#45584e` | 主按钮、进度、身份 |
| 强调 | `#d9873e` | 焦点、异常点、一处只准一处 |
| 成功 | `#698c70` | 回执、已批准 |
| 本尊 | `#a06a32` + `#fff6e6` | Mochi 自己 |
| 暗场 | `#0f0e0c → #1b1815` | 只有 ACT1 与两个留白拍 |

**纪律**：暖橙是"稀有色"——全片只在真正需要指认的那一处出现（异常数据点、授权键、光点）。任何时刻画面里的暖橙面积不超过 3%。

### 2.2 字体

正文 PingFang SC；**标题 Songti SC（宋体衬线）**——这是当前产品的真实标题字体，也是这条片子气质的来源。片中的"字"必须少：全片台词不超过 **9 句**。

### 2.3 动效纪律

- 曲线：`power3.out`（入场）、`power3.inOut`（位移/归并）、`power2.inOut`（镜头）。产品内 UI 用产品自己的 `cubic-bezier(0.22,0.78,0.24,1)`。
- 过冲上限 **2%**。禁用大幅 `elastic`、`back.out(>1.3)`、卡通弹跳。
- 禁止：glitch、spin、zoom blur、whip pan、幻灯片式 wipe、每个镜头都推镜。
- **每个镜头只有一个观点。**

### 2.4 镜头语言

把 Mochi 当工业产品拍：`macro push`（对焦某一行字号）、`shallow perspective`（≤6° 的面板旋转）、`controlled parallax`（三层景深：背景纸面 / 中景窗口 / 前景光标）、`camera travel`（沿界面横向巡航，而不是切镜）。**任何时候 UI 必须读得清**——为"电影感"把产品拍虚，一律不要。

## 5. 转场图（物件驱动链）

每一处转场都必须是"上一幕里已经有的东西"长成下一幕。**不允许随机 crossfade。**

```text
[黑]
 └─ 光标一闪 ──────────────► 输入点
     └─ 窗口累积 ──────────► 一整个工作区
         └─ 全部碎片 ──────► 收拢成光点
             └─ 光点 ──────► Mochi 本尊（球 → 小电脑）
                 └─ Mochi 的回答卡 ──(光标拉出)──► 真实文件卡
                     └─ 文件被读 ──► 提纲块 ──► PPT 页面骨架 ──► 真实 .pptx
                         └─ .pptx 末页的表格单元格 ──► 成绩表
                             └─ 单元格 ──► 图表
                                 └─ 异常数据点 ──► 几何点
                                     └─ 几何点 ──► 切线与模型
                                         └─ 模型节点 ──► 知识节点
                                             └─ 文件里的人名 ──► 学生对象
                                                 └─ 学生对象 ──► 校园协作关系
                                                     └─ 确认卡 ──► 教室「已看到」回执
                                                         └─ 主界面退后 ──► rail
                                                             └─ 万物 ──► 归位 ──► Mochi 字标
```

共 **14 处转场，零 crossfade，零切镜**（两处例外：ACT1 结尾的"突然静止"与 ACT8 结尾的"黑暗回来"——这两处要的就是硬切）。

## 8. 制作路线与技术规格

### 8.1 架构（关键决定）

**界面用代码重建，不用录屏。**

理由：①界面此刻仍在改，录屏一改就过时；②录屏做不出"物件驱动"的连续转场；③代码重建可以由 `tokens.json` 驱动——**界面改了只重抽令牌再渲染，影片自动跟上**。

界面重建不靠手绘想象：所有色值/字体/圆角/间距取自 `jxl-theme-bridge.css`，所有本尊几何取自 `ExpressiveOrb.tsx` / `OrbCompanion.tsx`。

### 8.2 本尊的动作：直接复用同一台引擎

`client-plugins/jxl-brand/src/vendor/bloub/`（bloub 0.1.1，MIT，含 LICENSE 与 SOURCE.json）是产品里驱动 Mochi 的同一套代码。影片把它搬进浏览器，用**时间轴时间**去 `engine.sample(t)`——逐帧确定，且银幕上的 Mochi 与产品里的 Mochi 是同一只。

### 8.3 合成约定（V7 已验证）

```html
<main id="film" data-composition-id="mochiV8" data-width="2560" data-height="1440"
      data-duration="220" data-fps="60">
```

- 时间轴 `gsap.timeline({paused:true})`，末尾 `window.__timelines.mochiV8 = tl`
- 所有待入场元素初始 `visibility:hidden`；**禁用 `Math.random`**（逐帧渲染必须确定）
- 改时长要同时改 `data-duration` 与 audio 的 `data-duration`

### 8.4 每次都要跑的三道闸

```bash
cd promo/v8
npx hyperframes lint .            # 必须 0 error 0 warning
npx hyperframes render --fps 60 --quality high --workers 1 \
  -o ../output/Mochi_220秒_旗舰产品片_V8.mp4
/opt/homebrew/bin/ffmpeg -ss <t> -i <out> -frames:v 1 ...   # 抽关键帧逐帧验
```

### 8.5 已完成

- `promo/v8/assets/`：字体（软链）、`gsap.min.js` 与 `music.wav`（硬链）、许可随附
- `promo/v8/tokens.json`：从源码抽出的机器可读真值
- `promo/v8/index.html`：ACT1–ACT3 完整合成（90s / 2K / 60fps），lint 0 error 0 warning
- `promo/output/Mochi_V8_ACT1-3_90秒.mp4`（16.3MB / 2560×1440 / 60fps / 5400 帧）
- 渲染速度基准：2K60 单 worker ≈ 2.5× 实时（90s 用 3m38s）

## 10. 附：已知缺陷（顺手查到，未擅自改）
