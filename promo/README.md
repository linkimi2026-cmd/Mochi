## 文件分工

- `v4/`、`v5/`、`v6/`：各版 HTML 时间轴、媒体与音频；存在跨版资产引用和软链，保留路径。
- `inputs/`：构建脚本仍需的轻量、可分发输入；不得继续引用个人“测试”目录。
- `output/`：MP4、字幕及渲染工具工作目录；交付时选具体 MP4，不打包整个目录冒充成片。
- `evidence/`：导出实际帧、参数与验收记录。
- `README-film*.md`、`storyboard-v3-90s.md`：早期制作说明，只在其版本范围内有效。
- `../docs/reference/user-materials/Mochi_宣传片制作经验与动作施工规范_V5.docx`：用户提供的制作参考；后续用户修正优先。

## 后续若继续剪辑

保留课件、建模、试卷/练习、校园网页与后端说明、查找学生、批准放行、沟通老师、Agent to Agent、课件接收及 Agent 预设。源界面为核心；打字、发送、点击、字体与转场连续；无实线/虚线轨迹。**哪里缺才补哪里，不把目标时长平均分摊造成慢放。**

成片参数与原始素材帧率分开表述：2K120 是输出规格，不能宣称所有录屏原生 120 fps。背景音乐与字体许可见 `licenses/`；Kimi 审片音轨的历史文件不自动获得对外传播许可。

## Git 与本地媒体边界

Git 保存各版 HTML、时间轴、构建/验证脚本、说明文档、`inputs/` 和 `licenses/`。原始录屏、界面帧、字体、音频、渲染输出与 QA 抽帧体积较大，保留在本机对应目录并由 `.gitignore` 排除；当前对外成片由根目录完整交付包承载。新电脑继续剪辑前需要从项目归档恢复这些本地媒体，不能只凭 Git 仓库宣称可重渲染。
