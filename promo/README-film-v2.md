# Mochi · 140 秒真实工作故事

交付目标：面向评委与采购方的横版产品演示。仅展示 Mochi 实际界面，故事为“准备明天的课，接着完成校园事务与协作”。

## 内容与制作

- 0–12 秒：选择工作区、工作模式与教学生成权限。
- 12–49 秒：操作三角形互动模型，输入并发送练习需求，真实生成过程加速节选，点击答案得到反馈。
- 49–88 秒：班主任待办、学生档案、自然语言查询登记状态、确认并批准虚拟放行申请。
- 88–133 秒：教师 Mochi 向管理员 Mochi 发起教室使用问询；管理员确认回话；教师收到完成回执。
- 133–140 秒：品牌收尾。

22 次真实操作对应鼠标、随行焦点与点击波纹；输入框带轻量聚焦描边。相机与指针共用源画面坐标，输入逐字出现使用实际输入采集帧。长等待剪短，关键结果保留至少 3.5 秒。字幕与相机移动为后期制作，产品内容没有重新绘制或伪造。

主要界面素材采集尺寸为 3840×2160；练习输入与生成段原始素材为 1600×900。素材按连续采集帧编码，源采样率低于输出帧率；60fps 是合成运镜和输出规格，不代表原始录屏全部为 60fps。最终输出目标为 1920×1080、60fps、140 秒。

## 已验证范围

校园功能在本地演示数据库运行。放行申请和 A2A 都由真实工具调用完成；A2A 使用两个独立 Mochi 运行实例、两个不同角色的演示账号以及实际 relay，并经过接收方确认。不能据此把影片描述为跨两台物理设备或 Windows 实机录屏。

用户已确认 Windows 一体机功能全部正常；本制作未重新进行硬件实测。查询展示登记状态，未把“在途、尚未确认到达”改写成实时定位。

权限存在模式差异：教学生成段展示“完全权限”；校园审批段使用“工作区内修改”并点击原生“允许一次”。当前完全权限预设关闭人工确认，会自动拒绝需要确认的校园写入操作，因此不宣称完全权限可直接完成所有审批。

先前接口缺失、自动拒绝等失败尝试未作为成功镜头使用。当前演示服务已使用现有迁移更新本地数据库，操作前留有备份，未迁移远程数据库。登录与密码没有录入影片。
