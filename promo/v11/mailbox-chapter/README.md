# Mochi 叮咚与小信箱

18秒新增章节，使用产品 `popupPageHtml()` 和 `LanPanel`，不是重绘产品。原生弹窗模型从已存的小陈提问记录产生标题、正文、时间和收件ID；点击位置从真实“打开 Mochi”按钮的几何位置计算。弹窗退出与小信箱进入共享同一舞台。

消息和身份来自隔离演示库，已读状态与原始记录一致。本次是历史到达/打开过程的原组件重放，不声称新增发送或新增已读。只读适配拒绝POST；未录制的个人档案返回空值，连接设置不在画面中。产品源码不修改。

原生弹窗位于独立iframe，保留原CSS与布局。小信箱也使用独立900×840视口，避免影片标题样式、镜头变换和产品滚动互相影响。原弹窗自主计时在离线重放中暂停，舞台由GSAP确定性驱动。光标保持48×60固定比例，只有独立点击光环缩放。

构建：`node promo/v11/mailbox-chapter/build.mjs`。
检查：`promo/node_modules/.bin/hyperframes check promo/v11/mailbox-chapter --at 2,4.8,5.2,7.7,10,15.8 --json`。
渲染：HyperFrames0.8.36，2560×1440，120fps，单worker。

排版检查的红框只属于私有检查截图，不用于影片或交付预览。所有用户预览须从实际MP4抽取。`snapshots/`、证据、原始数据和渲染输出被Git忽略。当前自动检查零错误零警告；不等同正常播放或长片全功能验收。

## 连续接信镜头

0–1.5秒，同一只后期信封横跨场景，缩入真实小信箱；1.5秒双音叮咚与信箱轻弹同时落点；1.55–2.75秒，原Mo从右下弹至中央，把信领出来；2.7秒翻开信封，3.3秒展开原生通知；5.15秒真实按钮位置出现点击反馈，6.15秒进入完整小信箱。信封属于后期道具，不是新增软件界面；无红框、无引导实线或虚线。

原Mo动画依赖既有 `motion-pass/assets/native.js` / CSS / palettes，先构建motion-pass，再构建本章。新增双音为后期音效，运行 `node promo/v11/motion-pass/mail-delivery-audio.mjs`，在两版已有独立配乐和共同点击声上混入同一提示声；不改原音轨文件。
