# Mochi V11 第一版联片

本版用于用户审查整体节奏、故事线、视觉与音乐，不称全功能正式版。按照用户要求先联合已有素材，不再等待新一轮模型连接或补录。目标输出 2560×1440 / 120 fps，约 3 分 55 秒；最终指标以 evidence/export.json 为准。原窗口录屏是可变帧率/60fps，120fps是合成与交付帧率，不是所有画面的原生采集帧率。

## 剪辑主线

首页与预设 → 多 Agent 分工及四款 Mo 配色 → 课件修订、PDF与成绩图表 → 实际交互模型 → 教室预约回复、提问、叫人和已读回执 → 嘉行联学生查询与申请登记 → 日记、偏好、历史与自动化 → Mo 结尾。

五个既有章节保留已经完成的折纸、三列反向滚动、字形进入和独立固定比例鼠标。补段采用真实窗口裁切、等比镜头移动、交替左右排布和动态标题。全片统一音乐，五处章节交接使用短叠化；后续可在审片意见基础上强化物体跨章节连续性。

## 重建

在仓库根目录运行 `node promo/v11/master-preview/build-supplement.mjs` 准备已录素材与补段HTML。再运行 prepare-render-parts.mjs 分为36秒校园与56秒日常两段。沿用 promo/node_modules 中现有 HyperFrames 0.8.36，以120fps、standard、CRF17、1 worker分别导出 assets/campus-rendered.mp4 与 assets/daily-rendered.mp4，随后使用 finish-supplement.mjs 合成 supplement/output/continuation.mp4。本轮校园段复用了取消大渲染前已经完成的前36秒，已解码验证；其余单独导出，避免4个浏览器同时载入13条媒体造成内存压力。然后 `node promo/v11/master-preview/assemble.mjs` 合片、生成 timeline.json 和统一音乐。

已有章节可独立重建，见各自目录。所有媒体、渲染快照与输出在本目录 .gitignore 中排除，不纳入 Git；字幕、剪辑脚本、来源入出点和复用依据纳入 Git。默认重新编码各段，避免剪辑修改后误用旧缓存；仅在确认输入与剪辑都未改动的失败恢复时使用 --reuse-encoded-parts。

## 检查

补段首轮快照发现中文编码和句末孤立标点问题，已在导出前修复，复核快照见 evidence/type-fixed。完整视频需检查：解码错误、分辨率、实际帧率与帧数、音轨峰值、章节接缝、关键中文标题和结尾。当前没有人声旁白，使用画面标题与连续配乐。
