# Mochi · 作品说明

**参赛**：嘉祥教育集团「拥抱 AI，智绘未来」中小学生 AI 创意实践大赛 · 高中组

---

## 一、作品名与一句话简介

**Mochi** —— 一个跑在老师办公电脑上的校园 Agent。

老师在对话框里说一句人话，Mochi 去真的查校园系统、真的生成文件；凡是要动到真实世界的动作（发通知、登记放行、创建医务记录、投递口信），**必须由老师亲手点「允许一次」才会发生**。

一句话：**AI 负责逼近，人负责把关。**

## 三、解决的问题：老师的时间，是被切碎的

这个问题的画面很具体——一位班主任的上午：

- 早读前，想知道**谁在外面、谁没回来**：要开电脑、登进校园系统、翻流动单；
- 第一节课间，宿舍那边来了条异常：他在走廊上，不在电脑前；
- 第二节下课，学生说要去医务室，他要登记、要盯返班；
- 中午想备下午的课，发现素材还散在三个文件夹和一本教材里；
- 傍晚想起来这周的班级情况要汇报，数据得重新凑一遍。

**这些事单件都不难，难的是它们不断把"教学准备"切碎。** 老师真正的专业时间，被消耗在"查一下、填一下、发一下"上。

Mochi 要做的不是再加一个聊天框，而是**把这些"查一下、填一下、发一下"接过去，并且在会出事的地方停下来问人**。

## 四、它是什么（讲人话）

- **它是老师桌面上一个能双击打开的 App**：Mac 和 Windows 都有安装包，不需要装开发环境，不需要开终端。
- **它会调用校园系统里的真实工具**：查学生状态、发起放行申请、创建医务记录、发通知、投递口信、检索本机教材库、生成 Word / Excel / PPT / PDF 真格式文件。不是在对话里"模拟"一遍。
- **它每一步都可能停下来问人**：会改变真实世界的动作，模型不能自己拍板，必须老师点确认卡。
- **它有自己的边界，而且边界是写进代码的**：疾病预警、学生风险评分、心理测评、生物识别、定位——这些**一条都不做**；学生的请假与放行**永远路由给老师**（依据：`docs/agent-integration-handbook.md` §1.2「做事边界」，原文即为"硬红线，任何 Agent 都不得实现"）。

### 三个端

| 端 | 载体 | 关键性质 |
|---|---|---|
| 教师端 | 老师办公电脑（Mac / Windows） | 主 Agent，全量工具 |
| 教室端 | 教室多媒体大屏 | **独立 Agent**：自己的模型、身份、数据根；不登老师账号；教师端不在也能独立干活 |
| 学生端 | 未来适配，**本期不做** | 保留设计 |

> 教师端与教室端是**两个身份之间的协作**，不是"同账号两台设备"（`docs/agent-integration-handbook.md` §1.1）。

## 五、怎么做的

### 5.1 底座：不自造一个"像 Agent"的外壳

Mochi 跑在 **DeepSeek 官方开源的 Agent 内核**上（`@deepseek-ai/dsh`，版本 `0.1.3-alpha.1`，MIT 许可；版本号可查 `apps/desktop/package.json` 的依赖钉版与 `docs/DOC-AUTHORITY.md` §6）。

这意味着它继承的是内核级的真实能力：多轮工具调用、子代理、会话轨迹、审批（waterfall）服务、插件装载契约。**Mochi 自己写的是"校园这一层"，不是轮子。**

### 5.2 自研插件 = 校园领域组合

打包白名单共 **26 项**（`apps/desktop/scripts/prepare-mochi-resources.cjs` 的 `PLUGINS` 数组，逐项可数）：

- **25 项是本项目自研**：服务端插件（校园业务、任务域/A2A、文件、文档、表格、演示文稿、图片与图表、教材库、成绩、记忆、定时任务、教学建模、双模式）+ 界面插件（品牌、主题、校园页、工作台、模型预设、局域网面板、模式切换）。
- **1 项是第三方内置**：`dsh-better-sidebar` 0.18.0（侧栏增强，MIT，来源 `github.com/omdsh-dev/DSH-better-sidebar`，见其 `package.json`）。

其中**校园业务插件 `mochi-campus` 注册了 26 个工具**（工具名可在 `plugins/mochi-campus/index.mjs` 里逐个 `register('...')` 数出来）。

### 5.3 人在环审批：这是产品结构，不是提示词

- 会改变真实世界的工具，在**实现里**先请求审批，只有结果是官方词汇 `allowed-once`（允许一次）才继续；否则抛出并如实告知"没有发出/没有登记/没有创建"（`plugins/mochi-campus/index.mjs`，全仓共 **14 处** `approval.request(` 调用点）。
- 审批适配器 `mochi-approval` **刻意不当"决策者"**：它只做安全委托，**绝不自己制造 `allowed-once`**；没有审批通道或返回词表外的值时，一律归为 `unavailable`（`apps/desktop/electron/dsh/mochi-approval/index.mjs`，官方结果词汇为 `allowed-once | rejected | cancelled | unavailable`，见 `docs/agent-integration-handbook.md` §8.1）。
- 交互层面还有一道：**对话界面默认把工具面收窄**，只剩"请求进入工作模式"这一个工具；老师点「允许一次」或直接切到工作界面，才拿到全量工具（`plugins/mochi-modes/index.mjs`、`modes.mjs`，用的是官方 `agent.ctx.tools.restrict()`）。

### 5.4 数据放在哪，什么会出网

- 老师的文件产物、会话轨迹、记忆库、教材索引，都落在**本机数据根**（打包态 `~/.mochi-home`，开发态 `.mochi-home.nosync`，教室端另有一个独立数据根；见 `docs/agent-integration-handbook.md` §11.1）。
- 教材库是**本机 SQLite**（`$DSH_HOME/knowledge/textbook.sqlite`，`plugins/mochi-knowledge/knowledge-store.mjs`）。
- **诚实说明**：对话内容会被送到**第三方模型端点**做推理——默认对话模型走 `https://mimo.ezlook.top/v1`，看图走 `https://aiaaa.cc/v1`（端点可查 `plugins/mochi-llm-mimo/index.mjs` 与打包内的 `settings-defaults.json`）。所以准确的说法不是"什么都不过网"，而是：**文件在本地、教材库在本地、身份与密钥在本机；而你要模型干活，上下文就必须到模型端点去。** 这一条在《伦理与社会影响》里单独展开。

## 七、和别的参赛作品有什么不一样

不比较优劣，只说清楚三条客观差异：

1. **底座不是套壳**。多数 AI 作品是"调一次模型接口 + 一个前端页面"。Mochi 跑在完整 Agent 内核上，工具是**注册进内核的插件**，能力可以一个个长出来，而不是塞进一段提示词里。
2. **交付形态不是网页 Demo**。它出了 macOS 与 Windows 两个平台的安装包（数字见 §六），老师装完双击即可用，**不需要填 API key**。
3. **"人要不要把关"被做进了架构**。审批门、工具面收窄、硬红线清单，都在代码里；换一段提示词不会让它们消失。

顺带一提，**这份作品说明和参赛 PPT 里的一些页，本身就是 Mochi 生成 / 参与生成的产物**——它交回来的不是一段文字描述，而是能打开、能继续改的文件。

## 八、现场演示什么（5 个场景）

场景名取自项目的演示计划（`docs/tasks/MOCHI-URGENT-REPLAN-2026-09-11.md`，第 60 行与第 124 行两处口径一致）：

| # | 场景 | 现场说什么 | 现场风险（提前知） |
|---|---|---|---|
| 1 | **校园传话** | 给同校同事的 Mochi 带一句口信；**发送前弹出确认卡**，老师点「允许一次」才投递；是否答应由对方本人决定 | 传话走的是**校园服务**（`/api/assistant/relay/send`），演示前要先把校园地址配好 |
| 2 | **PPT 二次编辑** | 让 Mochi 打开一份已有课件改其中几页，产出仍是 `.pptx` 真格式 | 依赖本机有 LibreOffice 才能做渲染回看（`docs` 有对应说明） |
| 3 | **成绩分析** | 从表格里读取成绩、算统计、产出可交付的 Excel | 公式引擎现已修好并有回归测试（见《伦理与社会影响》§三） |
| 4 | **教学建模** | 让 Mochi 生成一个可交互的教学模型，并说明它自己怎么验证 | 依赖内置的本地绘图资源，不联网 |
| 5 | **对话内审批** | 展示"对话界面工具被收窄 → 请求进入工作模式 → 确认卡 → 全量工具"的完整过程 | 这是最能说明"人在环"的一屏，建议排在最后 |

**演示前必须做的一件事（否则场景 1/3/5 会当场挂）**：安装包默认**没有配置校园服务地址**——`runtime-profile.json` 里 `campusApiUrl` 为 `null`，插件会回退到本机 `http://127.0.0.1:8787`（`plugins/mochi-campus/connection.mjs`）。演示机上要么起好校园服务，要么把地址配好并**当场验一次**。这条已经被写进审计报告（`docs/AUDIT-CODE-2026-09-12.md` 缺陷 7）。

> **每个场景的逐条降级路径，另见同目录的《演示脚本与降级路径.md》**（写给现场操作的同学，含台词、步骤、预期画面与切换阈值）。
> **特别注意场景 2**：9/11 那个安装包里**没有**课件二次编辑所需的插件，若现场用的是旧包，该场景必须改用降级版本讲，或先按 `docs/build-standard.md` 重出包（见 §九第 5 条）。

## 九、已知限制（诚实清单）

这一节是这份材料里最该被认真读的部分。

1. **两个安装包都未做代码签名与公证**。Mac 首次打开可能被 Gatekeeper 拦，Windows 会显示"未知发布者"，需要手动放行（`release/2026-09-09/Mac试用说明.md`、`Windows试用说明.md`）。
2. **Windows 包没有在真实 Windows 机器上人工验证过**。它由 CI 在 `windows-2022` 原生 runner 上构建、哈希与 CI 记录一致，但"安装、启动、界面流程由人走一遍"这件事**尚未发生**（`Windows试用说明.md` 自述）。
3. **校园真实网络与教室一体机未做现场验收**。局域网双端通知链只在**本机双进程 / 隔离双 HOME** 上跑通过，跨网段（不同 VLAN）自动发现可能不生效（`docs/DELIVERY-LEDGER.md` §二、`Mac试用说明.md`）。
4. **没有自动更新通道**。代码里没有任何自动更新组件（未发现 `autoUpdater` / `electron-updater`）。这不是理论风险——2026-09-12 已经真实发生过一次：已装好的机器因为工具名带点号而**整轮对话发不出去**，只能靠一个临时热修脚本救场；该热修包现已被项目自己判定为"绕过门禁的暗路"并作废（`docs/DECISIONS.md` D-002、`release/_voided-manual-hotfixes/README.md`）。
5. **现场演示用的安装包比源码落后一整代**：包内 20 个插件 / 7 个技能，源码已是 26 个插件 / 8 个技能（§六）。也就是说，PPT 里承诺的一部分能力，**在 9/11 那个包里没有**。
6. **依赖第三方模型端点**（`mimo.ezlook.top` / `aiaaa.cc`）。端点不可用或限流时功能会受影响；作品本身**不控制**这两个端点的可用性与数据政策。
7. **安装包内置模型密钥**（作者的有意决策），拿到安装包的人可以解出这两枚 key。风险、代价与治理方向写在 `docs/DECISIONS.md` D-001，本文《伦理与社会影响》§四也展开。
8. **安装慢的问题只修了一半**：老师的安装向导慢，根因是"要往磁盘上新建 41,150 个文件"（本机实测纯解压 28.5 秒，Windows Defender 逐个扫描才是十几分钟的来源）。已按规则排除 12,775 个运行时永不加载的文件（−31.0%），但剩余大头在 `asarUnpack` 上，**新数字要重出包后才能复称**（`docs/installer-install-speed.md`）。
9. **教材库是私有交付，不随安装包公开分发**；且**教材来源的许可情况不明确**（`docs/tasks/MOCHI-TEXTBOOK-IMPORT-01.md` 第 5 行原文）。这也是 §六里那一行标「⚠️ 待核」的原因之一。
10. **没有演示视频**，现场若崩没有兜底；**也没有外部真实用户的试用记录**（§六）。"节约了老师多少时间"这类数字，本项目坚持**只能用实际试用记录来报**，所以本文一个都没有写。
11. **CI 记录无法从本仓复现**：工作流文件在磁盘上（`.github/workflows/mochi-ci.yml`、`windows-native-package.yml`），但 `.github/` **没有被 git 跟踪**（`git ls-files .github` 为空，HEAD 停在 2026-09-07 的 `e568c16`）。因此 `docs/DELIVERY-LEDGER.md` 记录的那次 CI 构建，**在本仓看不到、也重跑不了**。
12. **校园业务侧跑的是同作者的校园系统，演示数据全为虚构**（`campus.nosync/README.md` 首段自述："不使用真实学生、教师或健康信息"）。⚠️ 该系统本身也是一件独立作品（有自己的`参赛材料`目录），**它与 Mochi 在报名材料里如何并列陈述，待作者与指导老师确认**。

## 十、一句话收尾

**Mochi 不是"老师可以用 AI 聊天的软件"，是"老师可以把事情交出去、但最后一下永远攥在自己手里的软件"。**

本项目最不打算做的事：把没验证过的能力说成已经做好。上面那份限制清单，和作品本身一样重要。
