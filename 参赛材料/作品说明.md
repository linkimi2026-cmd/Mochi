## 一句话介绍

Mochi 是一个运行在教师电脑和教室一体机上的校园 AI Agent：教师说出需求，它调用真实工具生成课件、试卷、文档、表格和模型，并连接校园系统完成查询、沟通和经人工授权的校园操作。

## 我们解决的问题

教师的一天经常被许多小任务切碎：找资料、做课件、整理试卷、核对表格、查找学生、联系老师、处理放行和返班。每件事都不复杂，但需要在多个软件、文件夹和角色之间反复切换。

Mochi 把这些工作放进同一个连续流程：

> 提出需求 → Agent 选择能力 → 展示执行过程 → 生成真实产物 → 连接校园角色 → 人工确认关键动作

## 作品组成

### Mochi

Mochi 是教师侧 Agent 与桌面工作空间，负责对话、工具调用、本地文件、课件与文档生成、表格、视觉、建模、知识、搜索、记忆、A2A 和教室连接。

### 联动计划

“联动计划”是独立的校园学生跨区域协同与安全闭环平台，负责校园账号、角色权限、学生流转、消息、审计、数据库和后端部署。Mochi 通过校园界面插件和校园工具插件与它连接，但不复制它的账号和数据权限。

桌面安装包只带审核后的校园静态客户端，不带“联动计划”源码、数据库或服务端凭据。真实校园查询和操作仍依赖已经配置并可用的校园 API。完整关系见 `docs/PROJECT-HISTORY.md`。

## 核心能力

| 场景 | Mochi 做什么 | 交付形式 |
|---|---|---|
| 新增课件 | 组织教学结构、生成并打开课件 | `.pptx` 等实际文件 |
| 整理试卷 | 根据目标与材料生成题目、答案和说明 | `.docx` / `.pdf` |
| 表格处理 | 读取、整理、计算并回写数据 | `.xlsx` / `.csv` |
| 教学建模 | 把简单问题转成可视化或模型产物 | HTML、图片或模型文件 |
| 知识与搜索 | 检索本地资料或已配置的联网搜索服务 | 来源、摘要和可继续使用的材料 |
| 查找学生 | 查询校园业务记录中的状态和位置 | 可核对的业务结果，不冒充 GPS |
| 沟通老师 | 通过 A2A / Relay 发送请求并等待对方回应 | 任务状态、回执和结果 |
| 批准放行 | 展示对象、目的地与影响，等待授权后执行 | 受控业务状态变更 |
| 教室连接 | 教师端向独立教室 Agent 发送通知或文件 | 局域网投递与人工“已看到”回执 |

## 使用逻辑

1. 首次进入选择工作区；演示时选择“全部允许所有权限访问”。
2. 默认聊天模式用于问答；执行课件、文件和建模任务前切到工作模式。
3. 输入需求并发送，观察分析、工具调用、生成和交付过程。
4. 打开真实产物检查内容；工作台用完及时关闭，避免遮挡界面。
5. 校园业务单独登录校园账号。查询和写操作遵守该账号的角色权限。
6. 放行、发消息等真实写操作必须由人确认；未确认就不写成已完成。

## Agent to Agent

Mochi 的特色不是把功能摆成菜单，而是让不同 Agent 和角色共同完成一件事。例如，资料 Agent 先整理材料，课件 Agent 生成 PPT，校园 Agent 查询相关学生，班主任或任课教师再决定是否批准业务操作，最后由 Mochi 汇总产物和状态。

系统区分“已发送、已送达、已完成、已拒绝和结果未知”。当投递结果未知时不自动重发，避免重复业务动作。

## 当前实现与交付

- 桌面应用版本：`0.1.0`。
- 平台：Mac arm64、Mac x64 和 Windows x64 均有当前磁盘交付物。
- Windows 一体机：用户已确认全部功能完成实测且正常可用；设备、系统和包哈希仍待归档。
- 当前默认模型种子：`mochi-aiaaa / deepseek-v4.1-flash`，支持文字与图像输入。
- 打包快照：496 项、91,963,676 字节，当前检查 0 缺失、0 不一致。
- 宣传片：V6 为 2560×1440、120 fps、100 秒；仍保留约 17 秒处过慢的用户反馈。

安装包和材料的精确路径、大小和证据层级见 `docs/DELIVERY-LEDGER.md`。

## 与普通聊天机器人的区别

1. **交付真实产物**：执行型任务需要生成文件，而不是只回复一段建议。
2. **连接真实业务**：可以在权限范围内查询校园记录和发起受控动作。
3. **人在回路中**：AI 可以准备和提议，关键业务由人批准。
4. **多 Agent 协同**：资料、课件、校园角色和教室设备能在同一任务链中协作。
5. **桌面工作区**：本地文件、权限、成果和运行状态有明确边界。

## 伦理与边界

- 不把校园业务记录描述成实时 GPS。
- 不让 AI 自动批准放行、医疗或其他影响学生的决定。
- 不把模型凭据、校园账号和文件访问权限混成一个权限。
- 演示数据必须使用虚构信息，公开材料不得出现真实学生敏感数据。
- 模型输出和自动生成的教学材料由教师复核后使用。

详细说明见 `参赛材料/伦理与社会影响.md`。

## 已知限制

- 校园 API 和搜索端点当前没有写死默认值，演示前必须显式配置并测试。
- 用户指出校园服务器报告有问题；本轮未重新部署或验证公网状态。
- 模型推理和联网搜索依赖网络及第三方服务。
- 安装包内置模型凭据是当前产品决定，也意味着凭据可能从安装包中被提取，需要限额、轮换和撤销治理。
- 当前没有证据证明 V6 的速度反馈已修复。
- 现有 PPTX 仍含旧数字和页码，必须更新后再提交。
