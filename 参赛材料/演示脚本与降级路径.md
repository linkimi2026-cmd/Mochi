## 1. 演示前 30 分钟检查清单

按顺序做，**每一项都要看到"通过"才继续**。任何一项没过，直接跳到该项后面的「没过怎么办」。

### ① 校园后端地址（最容易翻车的一项）

- **背景（这是真实缺陷，不是我吓你）**：打包版里 `campusApiUrl` 的值是 `null`，程序会退回 `http://127.0.0.1:8787`（那是开发机的本地地址）。也就是说，**新装的一台电脑默认连不上校园后端**，问它校园的事它会说连不上。
- **演示机怎么处理**：在启动 Mochi **之前**，先把环境变量设好，再启动：

  ```bash
  # macOS：先退出 Mochi，然后
  MOCHI_CAMPUS_API_URL=https://jyl-campus-health-entry.pages.dev open -a Mochi
  ```

  ✅ **环境变量这条机制已实测（2026-09-12 21:5x）**：直接调打包版的配置解析函数验证过——
  `resolveServiceDefaults({resourceRoot:'apps/desktop/resources/mochi-web', environment:{MOCHI_CAMPUS_API_URL:'https://jyl-campus-health-entry.pages.dev'}})`
  → 返回 `{"campusApiUrl":"https://jyl-campus-health-entry.pages.dev"}`；不设时是 `{}`（即确认了"默认什么都不注入、退回 127.0.0.1:8787"）。
  带路径的地址与乱写的地址都会被**明确拒绝**（只接受纯 Origin）。
  所以 **"设了环境变量就能覆盖"这条是成立的**——剩下要现场确认的只有一件事：网络真能通到那个后端。
  核实方法：启动后让 Mochi 查一次校园状态，看它返回的文字里有没有出现「当前结果来自已连接的校园 API」或「cloud-demo 演示数据」这两个字样。

- **没过怎么办**：如果设了也连不上，就当校园实时数据这一项今天不可用，把场景一和场景五换成下面写的降级版本讲——**如实说"演示机连不上校内服务，我用准备好的材料讲"**，比现场卡住强。

### ② 模型端点连通

- 端点地址：`https://mimo.ezlook.top/v1`（内置主力模型走这里）
- 怎么查：

  ```bash
  curl -s -o /dev/null -w '%{http_code}\n' --max-time 12 https://mimo.ezlook.top/v1/models
  ```

  - 返回 `401` = **端点通了**（没带密钥，被拒是正常的）
  - 返回 `000` 或超时 = **网络不通**，走降级
- **2026-09-12 21:2x 复核更正**：这条命令在作者开发机上实测是 `401（0.20s）`——**401 = 通了但没带凭据，是正常结果**；另有一次 `curl` 超时（exit 28）属于**偶发网络抖动，不要当成端点故障**。端点本身可用。
- 因此判据只有一条：**`000` 或持续超时 = 网络不通，走降级**；拿到 `401` 就是通的。
- 仍然必须在**演示现场的网络**（尤其校园网）实测一次：学校网络可能对第三方域名有额外限制，这与端点自身是否健康是两件事。

### ③ LibreOffice（没有它，有些"看起来成功"会变成"其实是失败"）

- 为什么重要：导出 PDF、把 PPT 渲染成图片回看、表格公式的"外部真算"，都要用本机的 LibreOffice。没有它，程序**会如实报错**（不会假装成功），但现场就做不成了。
- 怎么查（macOS）：

  ```bash
  ls /Applications/LibreOffice.app/Contents/MacOS/soffice
  ```

  能打印出这个文件 = 装了。
- 作者本机状态：已装，路径就是上面这个。
- **没过怎么办**：不要临场装（装一次要好几分钟还可能要联网）。改成只演示不依赖 LibreOffice 的部分（Word 文档生成、成绩分析工作簿、教学建模页面、传话、审批）。

### ④ 演示机上数据就位

- 要提前放好的东西：
  1. **一份成绩表**（.xlsx 或 .csv，放在机器上任何位置都行，但要记住路径）——成绩分析场景要用。
  2. ⚠️ 待核：是否要预先把课件生成出来一份放在桌面上（因为旧包做不了 PPT 生成，见场景二）。
  3. 校园账号已登录（见 ①）。
- **怎么判断就位**：让 Mochi 说一句「看一下今天校园情况」，它能给出条目而不是说"连不上"，就算就位。

### ⑤ 备用网络

- 准备一个手机热点，并且**在演示机里提前保存好**（不要现场输密码）。
- 校园网不通、模型限流时都靠它。

### ⑥ 兜底材料（这条最重要）

- 提前录好一段 3–5 分钟的不剪辑录屏（第 3 节有分镜），**拷到演示电脑本地**、再拷一份到 U 盘。
- 把关键产物（一份 PPTX、一份成绩分析工作簿）也拷到桌面，现场崩了可以直接双击打开讲。

## 2. 五个场景

> 每个场景的格式：**一句台词 → 操作步骤 → 预期画面 → 降级路径 → 建议时长**
> 「预期画面」里带引号的文字都是从源码里核出来的实际文案；标 ⚠️ 的表示我没能核实，请现场确认。

### 场景一 · 校园传话

**台词**
> "班主任要调一节课，得跟隔壁班老师商量。以前是翻通讯录、打电话、等回话。现在我跟 Mochi 说一句就行。"

**操作步骤**
1. （如果这一版有「对话 / 工作」两个模式的胶囊）确认当前在**工作界面**。没有这个界面的版本跳过这一步。
2. 在对话框输入：**"帮我问一下三年二班李老师，明天下午第三节课能不能换给我。"**
3. 看它是不是弹出**原生确认卡**（不是聊天里的文字按钮）。
4. 卡上会写明"投递给谁 + 投递什么内容"。让老师/评委看清楚了，再点确认。
5. 等 Mochi 回话。

**预期画面**
- 点确认之前，Mochi **不应该**说"已经发出去了"。
- 投递成功后，Mochi 会报告已送达（依据：只有服务器返回成功它才允许这么说）。
- 想展示"传话箱"：点侧栏底部的 **「教室连接」** 条目，或直接让 Mochi 打开传话箱。
  - 「教室连接」面板里的卡片标题有：「本机身份」「附近设备」「已验证候选」「相识与已配对」「通知与已看到回执」。
- ⚠️ 待核：传话成功时 Mochi 具体回哪一句话，请现场抄下来。

**降级路径**
- **校园网不通 / 没登录**：如实说"校内服务今天连不上，我讲一下它在这条链上做了什么"，然后改演示**场景五**（审批同样能体现"人拍板"这件事）。**不要**让同学临场假装点击成功。
- **模型限流**：换备用模型重试一次；再不行就走上面的降级。
- **程序崩溃**：切到本地录屏，找到传话那一段直接播。

**建议时长**：90 秒（现场演示时如果卡住，30 秒内必须切降级，不要硬等）

### 场景二 · 课件二次编辑

**台词**
> "老师最烦的不是做课件，是改课件。'第 3 页换个例子'——整份重做一遍。我们让它只改那一页。"

**操作步骤**
1. 输入：**"做一份勾股定理的课件，20 分钟，8 页，要有例题。"**
2. 等它生成，记下它返回的文件路径。
3. 接着输入：**"第 3 页换成生活中的例子，加一张表。"**
4. 打开生成出来的文件确认。

**预期画面**
- 生成物是一个**真的 .pptx**（能在 PowerPoint 里打开、能继续改），不是 HTML、不是图片。
- 改完第 3 页后，**第 1 版还在原来的文件夹里**，新版本写在另一个新目录里（这条规则在工具描述里写死了）。
- ⚠️ 待核：它回复里具体的路径文案。

**降级路径**
- **打包版没有这个工具（2026-09-11 的包就是这种情况）**：改成"打开昨天生成好的课件，我展示一下它的成果"，并**如实说明"现场这版安装包还没带上 PPT 生成，源码里已经做好了"**。诚实讲比演砸了强。
- **没有 LibreOffice**：不影响生成 .pptx，但会影响"渲染回看"这一步，别承诺现场看渲染图。
- **崩溃**：播录屏里的课件那一段。

**建议时长**：2 分钟

### 场景三 · 成绩分析

**台词**
> "考完试最花时间的不是改卷，是把分数变成能看的东西。我们让 AI 做统计，但**满分、及格线、优秀线必须由老师亲口说**——它不猜。"

**操作步骤**
1. 先把成绩表文件放到演示机上（提前放好，别现场找）。
2. 输入：**"这是高一(1)班期中数学的成绩表，路径是 …。满分 150，及格 90，优秀 120，帮我做一份分析。"**
3. 等它生成，打开生成出来的工作簿。

**预期画面**
- 生成物是**真的 .xlsx**（内部审计工作簿），里面有逐行的处理依据。
- 它会另外给一段**中文统计摘要**（及格率、优秀率这类）。
- **缺考/空白不会被当成 0 分**——这是写死在工具规则里的。
- 如果成绩表里有重复学号，它**整批标成"待核对"，不会自己合并**。

**降级路径**
- **方法一（推荐，最稳）**：用**老师给的表或虚构的演示表**，明确说一句"这是演示数据，不是真实学生成绩"。绝对不能拿真实学生名单上台。
- **工具不在包里 / 文件读不到**：改成展示已经生成好的工作簿文件。
- **模型限流**：等 30 秒重试一次，或者临时把问题缩小到"只算及格率"。
- **崩溃**：播录屏。

**建议时长**：2 分钟

### 场景四 · 教学建模

**台词**
> "有些概念，讲十遍不如让学生自己拖一下。我们让它现场生成一个能拖的模型。"

**操作步骤**
1. 输入：**"给我一个椭圆切线的交互模型，学生能拖切点。"**
2. 等它生成，用浏览器或自带的窗口打开生成出来的 HTML 文件。
3. 拖一下切点给评委看。

**预期画面**
- 生成出来是**一个自包含的 HTML 页面**（可以离线打开，不依赖网络）。
- 页面上应该能拖切点、有参数滑块、有"分步揭示结论"。
- 当前明确支持的模型类型是 **椭圆切线（conic-tangent）**——**不要现场承诺别的类型**（双曲线、抛物线等目前不在支持范围内）。

**降级路径**
- **工具不在包里**：打开提前生成好的页面演示（同样能拖）。
- **崩溃 / 浏览器打不开**：直接播录屏，或者展示生成的页面截图。

**建议时长**：90 秒

### 场景五 · 对话内审批

**台词**
> "前面几个场景你看到它很能干。但真正让我们放心的，是**它干不了什么**。"

**操作步骤**
1. 输入：**"三班的王同学身体不舒服，要去医务室，帮我登记一下。"**（⚠️ 待核：换成本校实际会用的说法；这里用的是虚构姓名，**不要用真实学生姓名**）
2. 它会先查学生目录，然后弹出一张**原生确认卡**。
3. 卡上会写清楚：谁代为登记、学生是谁、去哪、什么事由、预计多久、申请编号、当前状态。
4. **先不点**，让评委看清楚卡片内容再点「允许一次」。

**预期画面**
- 确认卡上的按钮是 **「允许一次」** 和 **「拒绝」**（这两个词是从官方组件里核出来的，不是我编的）。
- 点确认之后，Mochi 只能说这条申请是 **"待审批"（PENDING）**——**它不能说"学生已经获准离班"**，因为正式放行还要单独一步。
- 点「拒绝」的话，Mochi 应该报告"已取消，申请未登记"，并且**这一轮不再追问**。

**降级路径**
- **校园网不通**：改展示"**工作界面**"那张审批卡（如果这一版有双模式：在对话界面让它做一件要动手的事，它会弹一张写着「需要工作模式，继续？」的卡，你点「允许一次」它才拿得到工具）。这条在**没有校园网时也能演**——如果这版没有双模式，就改用已经拍好的审批卡截图讲。
- **模型限流**：直接讲卡片设计，不重试。
- **崩溃**：播录屏的审批段。

**建议时长**：2 分钟

## 3. 录屏分镜（3–5 分钟，不剪辑）

**录什么版本**：用**你真机装的那个包**录，不要用开发环境。理由：评委看到的应该是老师拿到手的东西。

**怎么录**：
- macOS 自带录屏，录**整个屏幕**（不要只录窗口，会看不到菜单栏角色图标）。
- 全程**不剪辑、不加速**。中途出错也保留——那反而更真。
- 分辨率 1080p 或更高；录的时候把分辨率调到你平时用的，别为了好看改成不常用的。

**分镜（建议顺序）**

| # | 时长 | 录什么 | 必须出现的东西 |
|---|---|---|---|
| 1 | 15 秒 | 打开应用 | 首次启动的角色选择框（标题「设置 Mochi 本机角色」，按钮「教师办公电脑 / 教室一体机 / 退出」）。**如果不再弹了**，就点菜单栏图标展示「当前角色：教师办公电脑」 |
| 2 | 45 秒 | 场景五（审批） | 那两张原生卡：写清楚内容的确认卡 + 按钮「允许一次 / 拒绝」。问完再点，节奏慢一点 |
| 3 | 90 秒 | 场景二或场景三（看哪版有） | 让它在屏幕上跑，**别把生成过程剪掉**（哪怕慢）。生成完一定要**真的打开那个文件**——看到 PowerPoint/Excel 里的内容才算数 |
| 4 | 45 秒 | 场景一（传话） | 发送前的确认卡 + 发送后的回执。传话箱界面如果能打开也录一下 |
| 5 | 45 秒 | 场景四（建模） | 真的用鼠标拖一下切点，画面要有变化 |
| 6 | 20 秒 | 收尾 | 打开存文件的那个文件夹，让观众看到**文件真的在硬盘上** |

**录完放哪**
- 建议路径：`参赛材料/媒体/mochi-现场演示-未剪辑-YYYY-MM-DD.mp4`
- ⚠️ 待核：这个目录目前还不存在（`参赛材料/` 下现在只有本文档和《教师使用手册》《真机验收记录》《作品说明》）。**建目录这件事我没做，请你手动建**——因为本次任务只允许我创建指定的三个文件。
- 同时拷一份到 U 盘。**不要只放在这台电脑上。**

## 4. 常见提问与答法

### Q1「这是不是 AI 帮你写的？」

**正面回答，不要绕。**
> "是。PPT 的排版、代码、文档，很多都有 AI 帮忙——**这本身就是作品在讲的事**。
> 我负责的是判断：什么值得做、做到哪一步该停、哪句话不能信。
> 您刚才看到的那个审批卡，就是我们把这句'人拍板、AI 提议'真的做成了产品里的一个东西，而不是写在纸上的口号。"

不要说的话："代码全是我自己写的。"——这句既不真，也没必要。

### Q2「你们删掉了什么？」

> "删掉的东西比加的多。
> 比如**对话模式**：我们故意让它只有"请求开始干活"这一个能力，其余工具全部收起来——省的不是性能，是**越权的可能**。
> 比如**发消息**：不管 AI 多想发，工具设计上就必须先弹卡、必须由人点确认，代码里写死了。
> 比如**医疗**：AI 在医务这条线上只做流转和通知，**不做诊断**，这是写进它人格里的红线。"

### Q3「AI 会不会自己乱发通知？」

**这是最该被问到的问题，答得越具体越好。**
> "不会，而且是三重堵死的：
> 第一，发送工具在调用前必须弹人工确认卡，模型自己点不了；
> 第二，校园服务那边还会再校验一次权限、身份和版本，AI 绕不过去；
> 第三，教室端收到通知后，「已看到」由**那台机器上的人**点，AI 不能代点。
> 另外它连"发现附近设备"都不等于"可以发"——配对必须人工确认过。"

### Q4「数据会不会传出去？」

> "学校最在意的不是功能多强，是数据会不会流出去。
> 三件事：教材知识库在**本机**、局域网传话是**校内直连**、敏感数据不进长期记忆。
> 还有一条我个人觉得最有意思的：**模型永远看不到密码**——认证是和模型分开走的，它连钥匙长什么样都不知道。"

⚠️ 待核：第 3 条有一些具体边界（比如记忆护栏的规则只有几条关键词），作者已知它**不完美**。如果老师追问细节，**如实承认"这里还有漏洞，在修"**，不要硬说万无一失。

### Q5「这个能在我们学校用吗？」

面试要诚实：
> "技术上已经能装起来用了（Mac 和 Windows 的安装包都有），但**我们还没在真实的学校网络和教室一体机上做过现场验收**，这块记录是空的。这也是我们接下来最想做的事。"

### Q6「哪里能看出这是学生做的？」

> "这份 PPT 里的每一张截图，都是在这台电脑上真的操作出来的；生成的文件真的在硬盘上。我也可以现在就让它现场做一份，您随便点。"
