# Mochi · 现场演示脚本与降级路径

> **status**: active
> **last_verified**: 2026-09-13
> **verified_by**: Codex（按当前产品逻辑重写；未在本轮完整现场走台）

## 演示目标

让评委在 6 分钟内理解一条完整故事：教师提出需求，Mochi 生成真实教学产物，再连接校园系统查找学生、沟通老师并由人批准关键操作。功能通过同一任务链出现，不逐项念菜单。

## 演示前准备

1. 使用最终 Windows 一体机和最终安装包；记录包哈希、系统版本和设备。
2. 选择“教师办公电脑”角色。
3. 选择专用演示工作区，并选择“全部允许所有权限访问”。
4. 校园服务使用已经核实的 `MOCHI_CAMPUS_API_URL`，不要依赖脚本里的历史默认地址。
5. 使用虚构演示账号登录校园系统；不要把账号密码展示在投屏或录屏中。
6. 准备一个简单、可快速完成的案例，避免现场生成超长课件或复杂模型。
7. 清理无关窗口、通知和个人文件；确认工作台可以随时关闭。
8. 预先打开最终 PPT 和宣传片，但不要用静态截图替代产品演示。

## 六分钟故事线

### 0:00–0:35 · 从一句需求开始

画面停在 Mochi 主界面。用鼠标明确指向模式切换，先从聊天模式切到**工作模式**。

输入：

> 为七年级制作一份 4 页“校园节水”课件，包含问题情境、两个知识点和一页课堂练习，保存到当前工作区。

完整展示打字、点击发送和开始生成。说明：“它会选择工具并生成真实文件，不是只回复一段提纲。”

### 0:35–1:40 · 课件生成和成品检查

展示分析、调用课件能力、写入文件和完成状态。生成过程过长时只在等待区适度加速，不跳过发送、工具调用和完成节点。

从成果或侧栏打开 `.pptx`。快速浏览封面、内容页和练习页，确认不是纯文字模板。展示完立即关闭工作台或预览面板，避免遮挡后续界面。

### 1:40–2:20 · 从课件继续到试卷

继续输入：

> 根据刚才的课件整理 5 道课堂练习，包含答案和简短解析，生成 Word 文档。

展示同一上下文如何继续工作，并打开实际 `.docx`。强调产物可以继续编辑和交付。

### 2:20–3:00 · 简单建模

输入一个保证可完成的短任务：

> 生成一个可交互的三角形模型，能拖动一个顶点，并实时显示三条边长。

展示生成过程和最终 HTML / 模型页面，拖动一次顶点证明它不是静态截图。完成后关闭预览。

### 3:00–3:25 · Agent 预设与搜索

打开 Agent 预设，用上下滚动或弹开动画快速展示课件、班会、学生跟进等预设，不逐个解释。

如果联网搜索端点已通过预检，询问一个与刚才课件相关的简单资料问题，并展示来源。如果端点未配置，直接说明本场不演示联网搜索，不临时切换未知公共服务。

### 3:25–4:20 · 查找学生

进入校园工作入口，确认已登录后回到主对话。输入：

> 林小禾现在在哪里？是否已经返班？

说明结果来自校园业务记录，不是 GPS。展示状态、最近登记和不确定性。如果查不到，要明确区分无记录、无权限和网络失败。

### 4:20–5:05 · 沟通老师与 A2A

继续输入：

> 把刚才的情况发给班主任，请他确认是否需要跟进。

展示收件人、内容和确认步骤。说明“发送、送达、对方接受和完成”是不同状态；Mochi 不替对方答应。

### 5:05–5:40 · 批准放行

使用虚构学生和简单目的地发起放行。让系统展示学生、班级、目的地和预计时长，演示者亲自点击一次性允许。操作完成后回读状态，证明业务闭环已经更新。

如果当前账号无权限，保留拒绝画面并说明 RBAC 生效，不切管理员账号强行通过。

### 5:40–6:00 · 收束

回到成果和任务摘要，让 Mochi 展示本次生成的 PPT、Word、模型，以及校园查询和协作任务状态。

收尾：

> Mochi 已至。让 AI 去执行，让教师做判断。

## 备用短版

现场只剩 3 分钟时，保留四个节点：

1. 切工作模式并生成 4 页课件；
2. 打开实际 PPTX；
3. 查询一名虚构学生；
4. 展示一次 A2A 或放行确认。

不要用 3 分钟同时演示课件、试卷、建模、搜索、记忆和全部校园角色。

## 降级路径

| 故障 | 现场处理 | 禁止说法 |
|---|---|---|
| 模型响应慢 | 保留发送和开始状态，切到同一版本预录的连续录屏 | “已经完成”但没有产物 |
| 搜索端点不可用 | 说明该服务未配置或暂不可用，跳过搜索 | 把缓存或旧截图说成实时搜索 |
| 校园 API 不通 | 展示健康检查失败，使用预录的同版本业务闭环 | “学生不在校” |
| 校园账号无权限 | 展示拒绝结果，说明角色权限生效 | 临时换高权限账号绕过 |
| 课件预览打不开 | 按实际输出路径用本机 Office / WPS 打开 | 把文字回复当 PPT |
| 自动发现失败 | 使用手动地址连接；仍失败就展示预录局域网流程 | 把同一 Wi-Fi 说成一定互通 |
| 工作台遮挡 | 立即关闭或收起工作台，再继续 | 带着遮挡硬演示 |
| 生成结果不理想 | 让 Mochi 做一次明确的小范围修改 | 现场重做复杂长任务 |

## 演示纪律

- 只用虚构数据和演示工作区。
- 不展示密码、模型密钥、令牌、个人目录和真实学生信息。
- 鼠标、点击、输入、发送、生成和完成都要让观众看得见。
- 不使用静态截图冒充正在执行；预录片段必须来自同一产品版本。
- 不为追求流畅而剪掉关键授权步骤。
- 工作台和预览用完就关，任何时候都不挡住主要操作。
