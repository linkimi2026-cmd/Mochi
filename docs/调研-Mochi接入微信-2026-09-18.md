# 调研：Mochi 接入微信 / 企业微信（扫码连 Agent + 息屏常驻）

> 调研日期：2026-09-18（第二版，含微信官方 AI Agent 技术文档）
> 一句话结论：**能，而且有官方通道——企业微信「智能机器人」已把 DeepSeek Harness（Mochi 内核）列为官方支持的 Agent 工具。WorkBuddy 走的就是这条路，Mochi 与 WorkBuddy 同根（dsh 生态），可直接复刻。**

---

## 0. 需求场景（用户原话拆解）

1. 老师没带电脑时，用**手机微信扫自己 Mochi 生成的二维码** → 连上微信 Agent 对话。
2. 电脑端要有「**息屏但 Mochi 仍在后台干活**」的能力（常驻、收消息、被需要时唤醒）。
3. 每个老师有**自己的 Mochi**，各自生成二维码扫码绑定。
4. 已读微信官方 AI Agent 技术文档，并参考 WorkBuddy 的做法。

---

## 1. 微信 AI Agent 技术文档（已读官方文档）

### 1.1 企业微信「智能机器人」（★ 重点，平台无关、官方支持 dsh）
官方文档：`https://developer.work.weixin.qq.com/document/61964` 与 AI 开放能力页 `https://work.weixin.qq.com/nl/index/aicli`

标准形态由三部分组成：
- **消息服务**：与企业微信服务端建立**长连接 / 接收回调**，把用户消息推给你的 Agent，并把回复送回。
- **Agent**：AI 服务（大模型 + Agent 框架），负责理解与生成。
- **CLI/MCP**：让 Agent 反向调用企业微信能力（文档、日程、待办、会议、微盘、通讯录……）。

官方「AI 开放能力」页**明确列出支持的 Agent 工具**：
> WorkBuddy、**DeepSeek Harness**、MiniMax Code、Kimi Work、Codex、企业自研智能体

安装方式（与 WorkBuddy 同款）：
```
npm install -g @wecom/cli
npx skills add WeComTeam/wecom-cli -y -g
```

**两种连接方式**：
- **长连接模式**：「无需域名或 IP 即可接收消息并返回结果」（腾讯云文档 `cloud.tencent.com/document/product/236/130927` 明确）。→ 对「电脑端息屏常驻」极其友好，不用公网域名。
- **URL 回调模式**：需公网域名 + HTTPS（Nginx 转发）。

支持群聊、私聊、流式输出、成员权限控制（「可使用成员」）。

### 1.2 微信个人版 ClawBot 插件（OpenClaw 专用，Mochi 不能直接用）
文档：`https://docs.openclaw.ai/channels/wechat`
- 微信通过腾讯外部 `@tencent-weixin/openclaw-weixin` 插件接入 **OpenClaw**；扫码登录走腾讯 iLink API。
- 关键：**这是 OpenClaw 的 channel 插件**，依赖 OpenClaw 的 channel 契约。Mochi 是 dsh，不兼容该契约，**不能直接复用**。
- 只支持私聊，不支持群聊；个人微信代理方案有封号风险。

### 1.3 微信小程序 AI / 公众号智能体（不适用本场景）
- 小程序 AI 开发模式（`developers.weixin.qq.com/miniprogram/dev/ai/integration.html`）是给「小程序」封装 SKILL 被微信 AI 调用，不是给独立 Agent 接微信。
- 公众号智能体发布（腾讯云 ADP）是「一个公众号绑一个智能体」，偏客服场景，与「每老师一个 Mochi」不匹配。

## 2. WorkBuddy 是怎么做到的（参考）

WorkBuddy 是企业微信官方 AI 开放能力**点名的 Agent 工具**之一，且它本身就是 dsh（DeepSeek Harness）生态产品。它的接法就是：

1. 企业微信管理后台创建「智能机器人」，拿到 **Bot ID + Secret**；
2. 在 Agent 侧装 `@wecom/cli` + `wecom-cli` Skill（MCP/CLI 方式）；
3. 用**长连接**建立消息服务（无需公网域名）；
4. 用户在企业微信里和机器人对话 → 消息经长连接推到 WorkBuddy → 处理 → 经长连接回发。

**WorkBuddy 与 Mochi 同根（都是 dsh）**，所以 Mochi 不是「借鉴 WorkBuddy」，而是「复用同一套官方能力」。

---

## 3. Mochi 能不能做到（能，且契合度极高）

| 需求 | 企业微信智能机器人方案 | Mochi 现状 |
|---|---|---|
| 微信里对话 | 企业微信里与机器人对话（老师需企微） | dsh 已被官方列为支持工具，装 `@wecom/cli` 即可 |
| 每老师一个、扫码绑定 | 每老师一个 Bot 实例 / 成员维度隔离 | Mochi 已有「每老师一个 agent + 身份治理」范式（mochi-lan 身份、mochi-dispatch 投递） |
| 息屏常驻收消息 | **长连接模式**（无需公网域名，WebSocket 常驻） | dsh 可常驻进程；参考 mochi-lan host-bridge 的常驻服务范式 |
| 反向调用校园能力 | CLI/MCP（文档/日程/待办/通讯录） | Mochi 已有 9 类工具（含嘉行联、日程/任务） |

**结论**：技术上完全可行，且比第一版设想的「企业微信自建应用 + 自写插件」更省事——直接走官方「智能机器人 + 长连接 + `@wecom/cli`」，Mochi 作为 dsh 是官方支持的一等公民。

## 4. 「每老师 Mochi 生成二维码扫码连」怎么落地

- **企业微信智能机器人**天然支持「成员维度」：后台可设「可使用成员」白名单；每老师配一个 Bot ID（多租户），或用同一机器人按成员隔离会话。
- **「二维码」映射**：
  - 企业微信内：老师把机器人加为联系人 / 拉进群即可对话（企微原生，无需额外二维码）。
  - 若坚持「个人微信扫码」体验：只有 ClawBot（OpenClaw 专用，**不可复用**）或「企业微信自建应用接个人微信」（社区方案 `openclaw-china/wecom-app`，有灰产/封号风险）。**不推荐**。
- **建议**：校园场景用企业微信最干净——学校通常已有企业微信，老师扫码/添加机器人即用，且合规、稳、支持群聊。

---

## 5. 「电脑息屏 - 人在工作」怎么落地

- **消息通道用长连接（WebSocket）**：企业微信官方长连接模式不依赖公网域名，电脑端 Mochi 常驻即可收消息；息屏只是显示器休眠，进程与网络不断就能收。
- **常驻进程**：把 Mochi 注册为系统后台服务，息屏不退、登录不退：
  - macOS：`launchd` 守护进程（~/Library/LaunchAgents 或 /Library/LaunchDaemons），配合 `caffeinate -d`（仅显示器睡眠、系统不睡）或系统设置「防止睡眠」。
  - Windows：注册为 Windows 服务 / 开机自启 + 电源计划「从不睡眠（仅关显示器）」。
- **注意**：macOS 真「系统睡眠」会断网，需开启「唤醒以供网络访问」或保持 `caffeinate`；长连接靠心跳重连兜底。
- 这正好复用 Mochi 已有的「host 常驻 + Connection 路由」范式（mochi-lan/host-bridge 已证明 dsh 可常驻并暴露受认证路由）。

## 6. 实现清单（先清单，未动手）

1. 企业微信管理后台为 Mochi 建「智能机器人」，拿 Bot ID + Secret（评估每老师一 Bot 还是成员隔离）。
2. 在 Mochi（dsh）装 `@wecom/cli` + `wecom-cli` Skill（MCP/CLI）。
3. 接企业微信「长连接」消息服务，把入站消息转给 Mochi agent（复用 `/api` Remote 编程入口）。
4. 回复经长连接回发；复用 mochi-dispatch 审批语义（对外发动作仍需人工确认）。
5. 把 Mochi 注册为系统后台服务，配置息屏常驻（launchd / Windows 服务 + 防睡眠）。
6. 每老师身份绑定：二维码/添加入口 → 绑定到该老师的 Mochi agent 实例。
7. 红线看护：微信消息不触发疾病预警/GPS/硬件禁区；预警只限流程异常。

---

## 7. 风险与注意

- **个人微信 vs 企业微信**：ClawBot（个人微信）是 OpenClaw 专用，Mochi 用不了；企业微信智能机器人是官方、稳、支持 dsh。**推荐企业微信**。
- **老师需有企业微信**：校园场景通常已具备；若学校无企微，需先开通或改走公众号/自建应用（成本更高）。
- **息屏 ≠ 系统睡眠**：需显式配置防睡眠/长连接心跳，否则 macOS 睡眠会断网。
- **红线**：同前，预警只限流程异常。
- **参赛节奏**：09-30 截止。企业微信智能机器人是答辩强亮点（多端触达 + 息屏常驻），但需排进剩余排期。

## 9. 结论（回应原问题）

1. **Mochi 能不能像小龙虾一样接微信？** 能。更准地说：能接**企业微信智能机器人**（官方、稳、dsh 一等公民），体验等同「微信里有个 Agent 随叫随到」。
2. **WorkBuddy 怎么做到的？** 它用企业微信 AI 开放能力（`@wecom/cli` + 长连接），且本身是 dsh 生态——Mochi 与 WorkBuddy 同根，直接复用同款官方能力，不必另造轮子。
3. **每老师二维码扫码连？** 企业微信智能机器人按「成员/Bot 实例」隔离即可；扫码体验可映射为「企微里添加机器人」。强行个人微信扫码不可复用 ClawBot。
4. **息屏-人在工作？** 长连接模式 + 系统后台常驻服务 + 防睡眠配置，技术上完全可行，且复用 Mochi 已有常驻范式。
5. **下一步**：先出「企业微信智能机器人接入」实现清单（附每老师实例化管理 + 息屏常驻方案），再动手——符合「先清单再迁移」节奏。
