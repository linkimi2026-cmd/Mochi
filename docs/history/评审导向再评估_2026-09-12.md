## 评委应理解的主线

Mochi 解决的不是“再做一个聊天机器人”，而是教师任务被文件、资料、校园查询和跨角色沟通切碎的问题。作品的核心价值是把真实执行、真实产物、校园连接和人工责任放进同一条 Agent 工作流。

## 当前优势

1. **真实产品形态**：有 Electron 桌面应用和 Mac / Windows 交付物。
2. **真实执行**：课件、文档、表格、视觉和建模任务有对应工具与文件产物。
3. **校园特色**：连接独立的“联动计划”校园系统，可查找学生、沟通老师和处理受控业务。
4. **Agent to Agent**：任务可以在资料、课件、校园角色和教室设备之间继续流转。
5. **人在回路中**：关键业务动作需要人工确认，权限边界可以解释和演示。
6. **现场基础**：用户已确认 Windows 一体机全部功能实测正常。

## 评分表达建议

| 评审维度 | 展示证据 | 避免 |
|---|---|---|
| 真实问题 | 一个教师从备课到校园协作的连续故事 | 功能菜单逐项朗读 |
| 人机协作 | AI 生成材料，人批准放行与消息 | 把 AI 描述成自动替人决定 |
| 创新 | A2A、独立教室 Agent、校园业务连接 | 只讲模型名称或参数 |
| 技术深度 | 工具执行、产物、权限、状态机和跨端连接 | 堆砌代码行数和内部包名 |
| 伦理 | 虚构数据、权限分层、不确定性和人工复核 | 宣称完全离线、零风险或绝不出错 |
| 完成度 | 最终安装包、真机证据、视频、PPT 和操作手册一致 | 用旧截图或旧数字 |

## 提交顺序

1. 填写作者与参赛信息。
2. 修复并重新导出 17 页 PPT。
3. 在“联动计划”复核校园服务和演示账号。
4. 补录 Windows 一体机最小证据。
5. 完整播放宣传片，确认节奏、字幕、乱码、遮挡和音量。
6. 计算最终文件哈希并更新 `docs/DELIVERY-LEDGER.md`。
7. 按比赛平台要求重命名、压缩和上传，上传后下载回检一次。

## 结论

作品能力和故事线已经具备参赛基础，但当前 PPTX 的旧数字、作者信息、校园在线状态和视频节奏反馈仍是提交前必须处理的具体问题。完成这些检查后再把文件标记为最终版。
