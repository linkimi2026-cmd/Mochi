# 自动上下文压缩与建模复用

## 根因与修复

已确认：DSH web-app 禁用宿主层的 compaction-basic、command-compact、tool-result-pruner，把这项能力交给角色预设。官方 standard 预设有独立压缩组，Mochi 的四个教师预设和 classroom 预设此前没有。依赖已安装不等于角色实际可自动压缩。

五个自定义预设现在按官方 standard 的结构挂载隔离组，复用当前 0.1.3-alpha.1 三个插件；不重复启用宿主压缩，不增加依赖或改模型默认值。隔离防止多个角色的压缩服务和监听器互相覆盖。

- 自动在模型步骤之间检查上下文压力：`auto: true`、`thresholdRatio: 0.8`、`retainRatio: 0.16`。
- 使用当前路由模型声明的上下文容量；不是固定聊天条数。模型未提供容量时无法按比例自动触发，需修适配器配置，不能随意猜容量。
- 先裁剪过大工具结果，再对较早消息生成摘要，保留最近对话；不能拆开工具调用与结果配对。手动 `/compact` 也挂载。
- 原始会话日志保留，摘要只替换下一次发送给模型的历史片段；摘要截断、空输出或不能缩小时不提交替换。恢复从日志重建摘要与最近消息。
- 使用当前会话模型，压缩有模型调用成本；无需用户每次主动要求压缩。它是有损摘要，不保证每个细节或图片像素都进入摘要。

公共规则增加摘要/恢复契约：原始任务、最新修正、约束授权、进度、最新路径/版本、回执、未检查范围与下一步；图片保留来源/页码，需要时重新读取。摘要不能升级授权、把渲染成功当视觉通过或导致重复外发。

## 验证

`npm run test:compaction` 使用真实安装的 Session、TokenMeter 和 BasicCompactionEngine，通过离线模拟传输验证五份实际角色配置的自动触发/缩小/恢复、截断失败保留源历史、关闭自动或低于阈值不调用。它不调用任何供应商，也不证明模型摘要语义完整。

本轮完整`npm run check`通过151项（原144项+7项自动压缩），0失败/跳过；受管profile生成与官方组合解析通过，建模工具原有生成/数值测试通过。

完整 profile 的接线与继续对话由 `apps/desktop/scripts/test-profile-skills.mjs` 验证，需匹配 Electron 原生依赖的运行环境。已在匹配Electron运行时实跑：standard、备课、成绩分析、资料试卷、教室协同、classroom共6个角色各自动生成一次摘要，随后继续回答；公共质量规则哈希一致。该探针使用离线适配器，不能冒称DeepSeek在线摘要质量测试。

## 科学建模先检索

物理、化学、3D、分子结构、键能关系与公式交互任务先按 [建模检索与复用](../skills/mochi/references/modeling-reuse.md) 搜 GitHub 完整项目/模型资产，再找组件。核对许可证、实际代码/文件、方程假设、依赖、维护成本及格式；适用则复用，部分适用就补差异，没有合适结果则自行生成。网络失败、无权限、无命中不能混为同一种结论。

当前 `mochi_model_create` 仍只支持椭圆切线。新规则没有把它变成通用科学建模引擎；其他模型须使用当前可用且获授权的工具。科学正确性、实际交互与视觉效果分别验收。

## 生效边界

改动属于源码与受管角色预设；已运行的进程和旧安装包不会因文件编辑自动更新。开发环境需加载更新后的预设并重新创建会话，安装版需更新打包资源。本轮没有重启用户 App 或改现有会话日志。
