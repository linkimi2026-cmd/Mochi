## 教室端（同日补充）

**用户指出**：PPT 里没有演示「教室端」和它的关系。

**调研结论（代码事实）**：

- 教室端 = **另一台独立运行同一套 Mochi 的设备**（教室多媒体大屏 / 一体机，Windows 为主），有自己的身份、模型、数据根，**不登录任何老师账号**
  - `Mochi-总体方案.md:52,57`；`apps/desktop/electron/dsh/launch-role.ts:39` 角色文案「教室一体机」；教室端用独立 home `.mochi-classroom-home`，不读教师端密钥/记忆/会话
- 两端关系是 **A2A 协作，不是同账号远程控制**（`docs/tasks/MOCHI-URGENT-08-LAN.md:5` 明确「不把 dsh Web 3090 开放到 LAN」）
- **只能教师端发起**：`plugins/mochi-dispatch/lan-transport.mjs:40` 只有 `role==='teacher'` 可发；目标必须同校、未拉黑、`role==='classroom'`（`:44`）
- 传输：UDP 广播发现 + HTTP 端口 **47832**；校园云 / relay 只是跨网备用，不是硬依赖
- 配对流程：本机身份（学校标识 + 班级 + 设备名）→ 附近设备自动发现（每 3 秒）→ 验证学校 / 班级 / 角色 / 指纹 → 教师发起相识 → 教室端人工接受
- 配对后能力：`mochi_list_classrooms`（只读名册，`mochi-dispatch/index.mjs:105`）、`mochi_notify_classroom`（发通知，`:106`）、`mochi_send_classroom_file`（发文件，`:112`）、教室端「我已看到」签名回执（`:188-251`）
- **能力边界**：文件仅 `.pptx/.docx/.xlsx/.pdf/.png/.jpg/.jpeg/.gif/.webp`，≤100MiB，SHA256 校验（`mochi-lan/lan-service.mjs:53-63`）；**不能远程控制 / 远程执行**；「打开软件 / 投屏 / 大屏通知横幅」属方案规划但**未实现**，不得写进 PPT
- 侧栏「教室连接」footerLabel（`client.js:878-882`）：`configured===false` → 「待设置身份」；创建身份后按发现状态显示「附近 N 台」等，**不会变成「已连接」**
- 角色由宿主锁定，浏览器 / 网页无法改（`host-bridge.mjs:52-54`）

**真实截图**：`参赛PPT/_shots/P-01-lan-panel.png` → `assets/ui-classroom.png`。面板原话可直接引用：「教师与教室各自独立身份；发现不等于相识，投递不等于已看到。」
